```

docs/            brief, roadmap, spec, ce fichier
```

Règle d'architecture : le cœur n'inclut jamais JUCE. L'adaptateur ne contient aucune logique métier.

Options CMake : `NEPTUNE_BUILD_PLUGIN` (ON), `NEPTUNE_BUILD_TESTS` (ON), `NEPTUNE_PROBE_TRACKS` (32), `NEPTUNE_WITH_LIBSNDFILE` (ON : libsndfile 1.2.2 + dr_flac, lecture des samples), `NEPTUNE_WITH_EBUR128` (**ON depuis le 2026-10-16** : libebur128 v1.2.6, LUFS du Master ; piège : `option()` met la valeur en cache, un dossier de build ancien garde OFF : passer `-DNEPTUNE_WITH_EBUR128=ON`).

## Build, tests, CI

- **Environnement de développement** : Linux Mint. `cmake` n'est **pas installé** et les bibliothèques de développement de JUCE (apt) non plus : le plugin complet ne se compile donc **que par la CI** ; les tests du cœur se compilent localement avec un `cmake` en environnement virtuel :

  ```bash
  python3 -m venv /chemin/venv && /chemin/venv/bin/pip install cmake ninja
  export PATH=/chemin/venv/bin:$PATH
  cmake -S . -B build -G Ninja -DNEPTUNE_BUILD_PLUGIN=OFF
  cmake --build build && ctest --test-dir build --output-on-failure
  ```

- **Pour compiler le plugin en local** : installer les paquets listés dans `.github/workflows/build.yml` (étape « Dépendances système »), puis `cmake --build build --target Neptune_CLAP`.
- **CI** : à chaque push, build + tests du cœur + `.clap` archivé (`Neptune-Windows.zip`, `Neptune-Linux.tar.gz`, `Neptune-macOS.tar.gz`). Durée : 4 à 6 minutes. Le job de **Release** sur tag `v*` n'a **jamais été exécuté**.
- **Récupérer un binaire** : `gh run download <id> -R jelhoste/flibuste-neptune -n Neptune-Linux`. Chrome bloque parfois les archives contenant un `.clap` non signé : envoyer le `.clap` brut, ou le copier dans `~/.clap/` (Reaper sous Linux le lit déjà) puis *Re-scan*.
- **Tests utilisateur** : Windows et Linux validés sur chaque jalon ; **macOS jamais testé** (il compile en CI).

## Pièges déjà rencontrés (à ne pas refaire)

1. **clap-juce-extensions n'a pas de vraies versions** : le tag `0.26.0` pointe vers un commit de 2022. On fige un commit de `main` (`7adee3a`, CI amont verte avec JUCE 8.0.11). JUCE est figé à `8.0.11` ; JUCE 9.0.x existe, la CI amont le teste aussi, non adopté par prudence.
2. **Noms de tests Catch2 en ASCII uniquement** : `ctest` les passe en ligne de commande et Windows casse les accents.
3. **Identifiants de paramètres** : le `clap_id` est le hachage du texte de l'ID de paramètre JUCE (wrapper). On utilise `std::to_string(ParamId)`. Les ids du cœur sont **stables** : ne jamais les renuméroter (automation des projets). Schéma de la sonde : maître 1–4 ; piste *t* à `1000 + 100·t` (+0 volume, +1 pan, +2 mute, +3 solo, +4 type, +10…17 bypass d'inserts, +20…27 niveaux d'envois).
4. **Paramètres discrets** : seul `isBoolean()` est marqué « stepped » côté CLAP ; les sélecteurs à N valeurs sont vus comme un paramètre normalisé 0–1 avec texte. Cela fonctionne dans Reaper (validé).
5. **Cœur lié dans le `.clap`** : `neptune_core` doit rester en `POSITION_INDEPENDENT_CODE ON`, sinon l'édition de liens Linux échoue (révélé par nlohmann/json).
6. **Aperçu de la maquette** : le volet d'aperçu de l'application charge un fichier HTML en `data:` sans ses scripts voisins ; servir `design/` en HTTP (`python3 -m http.server --directory design`).
7. **Taille de l'éditeur JUCE en dernier dans le constructeur** : `resized()` place les composants, il doit les trouver. Fixer la taille avant de les créer ne place rien tant que l'hôte ne redimensionne pas la fenêtre (Reaper sous Linux ne le fait pas : potards absents à l'ouverture, apparus au premier redimensionnement ; Windows masquait le défaut). Constaté le 2026-10-12.
8. **Contrôle de syntaxe de l'adaptateur sans compiler le plugin** : cloner JUCE 8.0.11 en partiel (`git clone --depth 1 --filter=blob:none --sparse`, `sparse-checkout set modules`) et clap-juce-extensions au commit figé avec ses sous-modules `clap-libs/clap` et `clap-libs/clap-helpers`, puis `g++ -std=c++17 -fsyntax-only -DJUCE_GLOBAL_MODULE_SETTINGS_INCLUDED=1 -DJUCE_STANDALONE_APPLICATION=0 -I<juce>/modules -I<cje>/include -I<cje>/clap-libs/clap/include -I<cje>/clap-libs/clap-helpers/include -Icore/include -Iadapter-juce/src -I<json>/include` sur chaque `.cpp` de `adapter-juce/src`. Attrape les erreurs de compilation avant la CI (ne vérifie ni l'édition de liens ni l'affichage).
9. **Installer un `.clap` sans passer par Chrome** : `gh run download <id> -n Neptune-Linux`, décompresser, copier dans `~/.clap/` (garder l'ancien hors de ce dossier : Reaper scanne tout ce qui s'y trouve), puis fermer les instances et faire Re-scan.

## Décision : sorties audio

**Jeu fixe de 32 sorties stéréo = 64 canaux** (décision du 2026-10-15 ; c'était 64 sorties stéréo = 128 canaux, le plafond du wrapper, depuis le 2026-10-11). Une sortie directe ou la sortie du Master pointant sur 33..64 (anciens états) est ramenée à 32 par le clamp d'`sanitisedStrip`. Raison : 16 pistes + 16 bus = 32 sources possibles, les pistes parallèles passent par leur parent ; listes plus courtes, moins de tampons remis à zéro. Anciennement : (décision de l'utilisateur, 2026-10-11) : les *templates choisis à l'insertion* de la roadmap ne sont pas supportés par clap-juce-extensions. Reaper n'active que les 2 premières sorties et laisse l'utilisateur activer les autres, ce qui suffit. Pas de second plugin « Stereo/Multi ».

## Constats du point 4 (lecture du code de clap-juce-extensions + validateur)

Établis par lecture du wrapper au commit figé et par `clap-validator` ; **le comportement réel de Reaper reste à constater avec la fenêtre de sonde**.

- **Sorties** : un port CLAP par bus JUCE, stéréo ou mono seulement. Le wrapper plafonne à **128 canaux de sortie** (Neptune en déclare 64 depuis le 2026-10-15). Les *templates de sorties choisis à l'insertion* ne sont **pas** supportés par le wrapper (`audio-ports-config` : 0 configuration ; le validateur le signale « non implémenté »). Les ports sont fixes ; décision à prendre (voir questions ouvertes).
- **Latence** : `setLatencySamples()` → le wrapper demande un **redémarrage** à l'hôte (`request_restart`, puis `latency_changed` à la réactivation). Utilisable pour les modes de l'IR loader, pas pour de l'automation.
- **Transport/tempo** : transmis via `AudioPlayHead` (tempo, mesure, position en temps, lecture/boucle) ; le wrapper coupe le bloc aux événements de transport.
- **Notes CLAP** : avec `supportsNoteDialectClap`, l'hôte peut envoyer des notes avec `note_id`. Le chemin standard du wrapper les convertit en MIDI JUCE et **perd le `note_id`** ; la sonde les prend donc en `handleDirectEvent`. `supportsNoteExpressions()` du wrapper n'est **pas utilisé** : les expressions passent obligatoirement par `supportsDirectEvent` + `handleDirectEvent`.
- **Modulation** : `clap_juce_parameter_capabilities` sur le paramètre (mono + polyphonique) ; la modulation polyphonique exige que le plugin émette `NOTE_END` (fait par la sonde).
- **Résolution des événements** : `CLAP_PROCESS_EVENTS_RESOLUTION_SAMPLES` vaut 0 par défaut : l'automation n'est **pas à l'échantillon près** (appliquée au début du bloc). À revoir avant le palier 1 si la précision compte.
- **État** : après un chargement, le plugin doit demander `params.rescan(VALUES)` à l'hôte (fait via `updateHostDisplay`). `setStateInformation` étant `void`, le wrapper répond « succès » même pour un état refusé (avertissement du validateur, sans conséquence).
- **Validateur** : `clap-validator` s'exécute en CI Linux (binaire épinglé 0.4.1) ; le zip contient une `.tar.gz` imbriquée.

### Constats de la sonde dans Reaper (Linux, 2026-10-11)

- Validé : 64 sorties stéréo (le routage affiche « 2/128 out »), latence modifiable à l'exécution (compteur et compensation), transport/tempo/signature.
- Notes jouées : arrivent en **événements CLAP** (compteurs « CLAP note-ons » et « NOTE_END » identiques ; « MIDI note-ons » reste à 0, normal : les notes ne passent pas par la voie MIDI de JUCE).
- **Reaper ne fournit pas de `note_id`** (valeur -1) pour les notes jouées ; l'adressage d'une note se fait donc par canal + touche, pas par identifiant.
- **Non déclenchés** : expressions de note et modulation de paramètres (mono/poly). Non testé : MPE, aftertouch polyphonique, modulation LFO/ACS de Reaper. Ne pas supposer que Reaper les émet ; à reconstater si le besoin apparaît (hôte susceptible de les émettre : Bitwig).

## Réglages et autosave (point 5)

- **Dossier de configuration** : `~/.config/Neptune` (Linux), `%APPDATA%\Neptune` (Windows), `~/Library/Application Support/Neptune` (macOS). Contient `settings.json` (créé avec les valeurs par défaut au premier lancement) et `autosave/`.
- **Réglages** (`Settings.h`) : langue (`en`), thème (`dark`, défauts de la maquette), contraste 0–4 (0), profil de performance (`live`), 4 dossiers par défaut (vides), `autosave_interval_seconds` (60 ; 0 = désactivé ; minimum 5), `autosave_keep_days` (30). Lecture tolérante champ par champ (jamais bloquante). Valeurs par défaut du profil (`live`), de l'intervalle (60 s) et de la durée de conservation (30 j) : confirmées par l'utilisateur. Pas encore de menu pour les modifier : on édite le fichier ; le réglage est lu une fois au démarrage de l'instance.
- **Autosave** (`Autosave.h`) : chaque instance a un identifiant de 32 hexadécimaux inscrit dans l'état du projet (`instance_id`). Elle écrit `autosave/<id>.neptuneautosave` (seulement si l'état a changé depuis le chargement ou la dernière écriture) et le supprime à la fermeture propre. Un fichier dont le processus propriétaire (pid) n'existe plus est la trace d'un crash.
- **Récupération** : à la relecture du projet, l'instance reprend son identifiant et retrouve son autosave ; s'il diffère de l'état chargé, il est conservé (`.neptunerecovered`) et proposé par une bannière Restore/Discard dans la fenêtre de sonde, jusqu'à ce que l'utilisateur tranche. L'autosave peut être plus ancien que la dernière sauvegarde du projet : la bannière affiche sa date.
- **Limites connues** : un pid réutilisé par un autre processus après un redémarrage ferait passer un vieux fichier pour « vivant » (il n'est alors ni proposé ni purgé). Deux pistes dupliquées portent le même identifiant : la seconde garde un identifiant neuf (sans récupération jusqu'à la prochaine sauvegarde du projet, qui l'enregistre). L'identifiant venant d'un état de projet, il est validé (32 hexadécimaux) avant de servir de nom de fichier.

## i18n et thèmes (squelettes, palier 0)

- **i18n** (`I18n.h`) : `Translator(code)` ; anglais par défaut, français disponible. Tables **compilées dans le plugin** (pas de fichiers à installer). Chaque texte visible a une **clé** (`recovery.restore`) ; clé absente dans la langue → anglais, clé inconnue → la clé elle-même (visible). Textes à trous `{0}`, `{1}`. Le nom « Neptune » n'a pas de clé. Un test vérifie : pas de doublon, anglais obligatoire, mêmes trous dans toutes les traductions. Ajouter une langue : une colonne dans `I18n.cpp` + `languages()`. `settings.json` accepte n'importe quel code de langue ≤ 16 caractères ; un code non supporté retombe sur l'anglais.
- **Thèmes** (`Theme.h`) : les 4 thèmes avec leurs **jetons de couleur copiés de la maquette** (mêmes noms, `tokenCssName()`), style de potard (led/pot), style de contrôles (glass/bezel/hc), rayons, épaisseur de bordure. `withContrast(def, niveau)` est le **port exact de `design/nova-contrast.js`** ; vérifié en exécutant le JS réel dans le volet navigateur : 163 valeurs sur 163 identiques (3 thèmes × niveaux 1–4). Le thème haut contraste n'est jamais modifié.
- **Pas repris** : les ombres (`--csh`, `--fsh`, `--ctl-sh`) et les dimensions des composants des contrôles (`nova-controls.css`) ; à décider quand les composants de l'interface seront écrits.
- **Branché** : seulement la fenêtre de sonde (couleurs depuis le thème/contraste de `settings.json`, textes de la bannière de récupération et de la latence via les clés). Pas de menu : on édite `settings.json`, lu une fois au démarrage. Partie adaptateur compilée par la CI (verte) et **validée dans Reaper par l'utilisateur** (langue, thème, contraste).

## Emplacements assignables du Sampler (2026-10-17, à valider dans Reaper)

Décisions de l'utilisateur : 16 emplacements par piste Sampler dans un pool commun, chacun vise une **zone ou un Groupe** ; valeur **relative et neutre à 0** ; 6 paramètres (attaque, décroissance, sustain, relâchement, niveau, accordage) ; assignation **rangée avec l'instrument** ; interface **fenêtre « Emplacements... » + menu contextuel**. Les enveloppes du sampler ne sont PAS exposées autrement (chaque zone a la sienne).

- **Paramètres** : `mixer::zoneSlotParam(track, slot)` = `12000 + 16.t + slot`, -100..+100 %, défaut 0 (16 par piste, déclarés pour les 16 pistes). **Assignation** : `InstrumentDescription::slots` (`ZoneSlots.h`) : par emplacement {paramètre, zone (indice dans la description) ou Groupe (nom)} ; JSON `slots` ; retirée avec la zone, décalée quand des zones disparaissent (`removeZones`, `pruneSlots` ; l'import « remplacer » libère les emplacements de zone, ceux de Groupe restent) ; annulable (copiée par `copySettingsFrom`).
- **Moteur** : `Instrument::slots` (Groupe résolu en identifiant au chargement), `SamplerVoices::setSlotAmounts` (lu par bloc), `resolveSlotMods` : temps x10^v (attaque, décroissance, relâchement), sustain x(1+v), niveau ±24 dB, accordage ±100 cents ; plusieurs emplacements sur une zone se cumulent. Pris au **Note On** ; le **relâchement est lu au Note Off** (le charley qu'on raccourcit pendant qu'on le tient). Pas de variation en cours de note (sauf le relâchement).
- **Interface** : bouton « Emplacements... » (vue Sampler, à côté de « Filtres ») -> `SlotsPanel` (fenêtre flottante, 16 lignes : cible = Groupe ou zone sélectionnée dans la liste, paramètre, curseur de valeur) ; clic droit sur une zone de la liste ou sur la case d'un Groupe -> « Assigner à un emplacement ».
- **À valider** : le menu contextuel, la fenêtre (disposition), l'effet sur un charley ouvert (relâchement x0,1), les emplacements après suppression de zones, annuler/rétablir. Les noms des paramètres dans l'hôte sont « Track n Slot k » (non renommables selon l'assignation).

- **Contrôleurs MIDI (CC)** : `applyControlChange` (OrganSynth.cpp), mêmes numéros que setBfree (tirettes 70-78 par voie de clavier, réverb 91, percussion 66/80-83, vibrato 92/95/30/31, overdrive 65/93, Leslie 1/64), branché dans **Orgamon seulement**. **Neptune** : les CC ne sont pas acheminés jusqu'aux pistes (décision de l'utilisateur : à réfléchir, c'est aussi une piste pour alléger les paramètres d'automation). « CTRL CH » de la maquette non repris : chaque clavier écoute ses CC sur sa propre voie, comme dans setBfree.
- **Câblage classique / étendu** (écrit, à valider) : le mode **classique** est le portage de setBfree tel quel (modèle « 91 roues, repli de 12 notes » et pondération par défaut : le 16' baisse d'environ 10 dB et le 16' des 12 touches graves sonne une octave plus haut ; vérifié par mesure). Le mode **étendu** (Réglages) ajoute : interrupteur du repli des graves et une grille 9 tirettes x 5 plages d'octave (−24 à +12 dB, interpolée) multipliée au modèle (`nb3_wiring`, `OrganDescription::extended / foldback / taperDb`). Fixé à la construction des tables : chaque changement reconstruit l'orgue (`OrganVoices::requestBuild`, comme l'accord), donc appliqué à la fin du geste. Réglage de la piste, ni preset ni automation. Les mêmes courbes valent pour le supérieur et l'inférieur (comme setBfree).
- **Pas repris** : MOTOR NOISE (n'existe pas dans setBfree), taille / amortissement de la réverb (setBfree n'a qu'un niveau), diaphonie (« leakage » : tables fixées à la création du moteur, comme l'accord), rayons / micros / filtres du Leslie (choix « essentiel »), page MATRICE de la maquette.
- **Choix par défaut à confirmer** (l'utilisateur n'avait pas de préférence) : trois claviers = trois canaux MIDI réglables (1, 2, 3)
  + points de split sur le canal du supérieur ; transposition par clavier ; touches hors étendue muettes.
- **Pièges** : les fichiers C de setBfree doivent rester sous `_USE_MATH_DEFINES` ; `strcasecmp` passe par `compat/strings.h` sous MSVC ;
  la CI (Linux, Windows, macOS) compile ce C.

## Module FM de type DX7 (2026-10-16, à valider dans Reaper)

Décisions de l'utilisateur : moteur **msfa** (Apache 2.0), périmètre « tout de la spec », **type de piste FM + plugin séparé**, enveloppes DX7 natives (4 vitesses / 4 niveaux). Cœur testé (16 tests) ; adaptateur contrôlé à la syntaxe seulement, **jamais écouté** : le son est celui de msfa, à valider à l'oreille.

- **Moteur** : `third_party/msfa/` (copie de `app/src/main/jni` de google/music-synthesizer-for-android, commit `f67d41d`, + `LICENSE-APACHE-2.0.txt` + `README-NEPTUNE.md` qui liste nos modifications : durée des segments indépendante de la fréquence d'échantillonnage, modulation d'amplitude AMS / AMD absente de msfa, étendue du pitch bend réglable, décalages d'unisson / glissando, masque d'opérateurs, niveaux d'opérateur et feedback en direct, `min`/`max` standard, `#pragma once`). État global au processus (tables de msfa) : deux instances à des fréquences d'échantillonnage différentes se partagent la dernière initialisation (limite connue). Les notes sont rendues par blocs internes de 64 échantillons (au plus 64 échantillons de latence sur un Note On).
- **Données** : `FmPatch.h` : patch de 156 octets = le format DX7 déplié (une voix en sysex = 155 octets + masque d'opérateurs) ; `kOperatorStride`, décalages nommés ; l'opérateur d'indice 0 est l'**OP6** du DX7 (ordre du sysex), l'indice 5 est l'OP1. Sysex : voix seule (163 octets) et lot de 32 (4104 octets), somme de contrôle vérifiée (une somme fausse est signalée mais le patch est chargé), octets parasites ignorés. **Non fait** : le bloc « function parameters » du DX7 en sysex (le modèle de données des réglages de voix est dans `FmDescription` et en JSON).
- **Voix** (`FmVoices.h`) : poly (limite 1 à 32, vol : plus ancienne / plus faible / garder les graves / les aigus), mono et legato avec glissando, unisson 1 à 8 (détune, répartition stéréo à puissance constante, normalisé 1/√n), molette (vibrato / trémolo), pitch bend 0 à 12 demi-tons, pédale de maintien (API `setSustain`, câblée dans le plugin séparé seulement). Macros automatisables (11 paramètres par piste, `fmParam`, offsets 60..70 du bloc de la piste) : brillance (modulateurs ±12 dB), vitesse des enveloppes (prise au début de chaque note), feedback / drive, niveaux des 6 opérateurs, détune et répartition de l'unisson. Les notes en cours gardent le patch avec lequel elles ont démarré (la capture par voix est donc naturelle pour le FM). Un niveau final de relâchement non nul ne s'éteint jamais seul : une note relâchée est coupée après 20 s.
- **Niveau** : une porteuse à 99 donne 1/8 de la pleine échelle (comme le DX7 : marge pour 8 porteuses) ; six porteuses à 99 donnent 0,75. Pas de gain de compensation ajouté ; le gain de la piste règle le reste.
- **Neptune** : 3e type de piste (`TrackType::Fm`, menu du type de piste du Mixeur), description par piste dans l'état (`fm`), vue `FmView` à la place du Mapping (page Opérateurs : diagramme d'algorithme interactif avec pastilles d'activation, panneau de l'opérateur, enveloppe graphique, mise à l'échelle du clavier avec mini-courbe ; page Global : LFO, enveloppe de pitch, voix, unisson, macros), import / export sysex (`FmSysexIO` : une voix remplace le patch ; un lot de 32 devient 32 presets dans une banque neuve), presets par le même gestionnaire (module `fm6op`, `FmPreset.h`, 4 presets livrés de notre cru, aucune donnée Yamaha ; `PresetHost::acceptsPreset` : chaque plugin ne montre que ses presets, la bibliothèque est partagée).
- **Plugin séparé « FM6Op »** (nom provisoire, `com.tournedosrossini.fm6op`, cible `FM6Op`, archivé par la CI sous `FM6Op-<OS>`) : `FmSynth.h` (moteur, volume et pan propres, état `fm6op-state`), `FmPlugin.*` ; mêmes presets et même vue.
- **Points à confirmer à l'oreille** : le niveau de l'AMS / AMD (approximation : 7 doublements au maximum, ~42 dB) ; la hauteur des opérateurs en mode fixe (formule de msfa) ; le glissando legato ; la macro de vitesse des enveloppes ; les 4 presets livrés (recettes classiques, jamais écoutées).

## Petit écran, capture par voix, presets dans Neptune, limite globale de voix, filtre MIDI avancé, LUFS (2026-10-16, à valider dans Reaper)

Lot écrit sur demande de l'utilisateur après validation sous Windows d'AnalogSynth. Cœur testé (338 tests) ; adaptateur contrôlé à la syntaxe contre JUCE 8.0.11 ; **rien n'est encore vu à l'écran ni compilé par la CI avant le push**.

- **Petit écran** (Neptune et AnalogSynth) : `ScaledRoot` (adapter) : tout le contenu de l'éditeur vit dans une racine dont la taille logique est au moins la taille de conception (Neptune 1100 x 760, AnalogSynth 820 x 600) ; en dessous, tout est réduit proportionnellement (échelle min 0,3) au lieu de se superposer. Taille de départ plafonnée à 90 % de la largeur / 85 % de la hauteur de l'écran utile ; limites 420 x 300 (Neptune), 360 x 240 (AnalogSynth). Le clavier à l'écran se **masque tout seul** quand la hauteur manque (`SynthView::placeScaled`, seuil 536 px logiques) ; le bouton « Clavier : auto / masqué / affiché » du bandeau d'onglets le force. Pièges : les enfants de l'éditeur sont déplacés dans la racine à la fin du constructeur (`adopt`) ; toute fenêtre superposée (modale, gestionnaire de presets, filtre MIDI, assistant d'import...) doit être ajoutée à `root_` et dimensionnée avec `rootBounds()`, jamais `getLocalBounds()` de l'éditeur ; le dessin de l'éditeur est `paintContent`.
- **Capture par voix** (décision : génération de preset) : à un changement de preset, les notes en cours gardent l'ancien patch ET les valeurs capturées d'avant (`SynthPatch::freezeRunningVoices`, `SynthVoices::setPatch` fige les voix actives avec `lastParams_`) ; les nouvelles notes prennent le nouveau ; ensuite les potards et l'automation n'agissent que sur la génération courante. L'ordre compte : **le patch est publié AVANT de changer les valeurs** (`AnalogSynthEngine::loadPreset`, `NeptuneProcessor::loadPreset`). Les anciens patchs sont gardés en vie par `SynthPatchKeeper` tant qu'une voix figée s'en sert (l'audio publie `oldestFrozenGeneration` puis `adoptedGeneration`, le publieur les lit dans l'ordre inverse). Une retouche du patch (édition de l'enveloppe) ne fige rien : les notes en cours suivent, comme avant. Limite : deux changements de preset dans le même bloc audio ne figent que le dernier.
- **Presets dans Neptune** : le synthé de la piste sélectionnée a la même barre de presets et le même gestionnaire qu'AnalogSynth (`PresetHost` : AnalogSynth et Neptune l'implémentent ; `PresetBar`, `PresetManager`). Même bibliothèque que le plugin séparé (`<config>/Neptune/AnalogSynth/` ou `presetsDir`) : les presets s'échangent. Les clés de preset sont celles de la piste 0 ; `idForTrack` les ramène à n'importe quelle piste. L'identifiant du preset chargé est sauvegardé par piste (`synth_preset` dans l'état du mixeur). Charger un preset est une seule entrée d'annulation. Le fader et le pan de la piste restent « libres » (jamais écrits par un preset).
- **Limite globale de voix** (décision : voix la plus faible) : réglage du Master (`max_voices`, 16 à 1024, 256 par défaut), toutes pistes Sampler et Synthé confondues ; au Note On, tant que la limite est atteinte, on vole en fondu la voix la plus à sacrifier du plugin (les voix en relâchement d'abord, puis la plus faible, puis la plus ancienne) ; les limites par piste restent. Réglable par un clic sur « Voix : n / limite » dans l'en-tête de Neptune.
- **Filtre MIDI avancé** (décision : complet avec logique booléenne) : `MidiFilter.h` : arbre de règles par piste (ET, OU, OU exclusif = exactement un, NON ET, NON OU, NON) dont les feuilles testent type (note, note on, note off, CC, pitch bend, aftertouch de canal et polyphonique, program change), canal, plage de la 1re donnée (note / CC / programme) et de la 2e (vélocité / valeur / pression / bend 0..127). Borné : 32 noeuds, profondeur 6, 8 enfants ; un groupe ET vide ne laisse rien passer. Sauvegardé avec la bande (`midi_filter`). **Seules les notes sont consommées aujourd'hui** par le moteur (le reste du MIDI n'a pas encore de destinataire) : les règles CC / bend / aftertouch / program sont évaluées et stockées mais sans effet audible. Un Note Off suit toujours le sort de son Note On. Bouton « MIDI » dans l'en-tête (piste sélectionnée), éditeur en arbre superposé.
- **LUFS au Master** : `Loudness.h` : libebur128 sur un thread d'analyse (l'audio ne fait que copier le signal dans un tampon circulaire sans verrou) ; momentanée, court terme, intégrée (gating, histogramme) et crête vraie ; test : un sinus stéréo de -23 dBFS mesure -23 LUFS. Affiché dans la bande Master (M, S, I, TP) avec un bouton de remise à zéro de l'intégrée. Désactivable (`-DNEPTUNE_WITH_EBUR128=OFF` : le compteur reste à « -inf »).
- **À valider dans Reaper** : la réduction de l'interface sur un petit écran (Windows) ; le masquage automatique du clavier ; un changement de preset avec des notes tenues (l'ancien son doit finir tout seul) ; l'éditeur de filtre MIDI avec un clavier MIDI ; le compteur LUFS pendant la lecture.

## Palier 1 — Synthé soustractif, premier jet + pistes actives (2026-10-13, à valider dans Reaper)

- **Pourquoi** : tester le mixeur avec des sons faciles à reconnaître (une note tenue, un niveau constant) plutôt qu'avec des samples. Réglages **par instrument**, sauvegardés avec lui (`polyphony`, `max_voices`, `voice_steal`, `same_key`, `cut_fade_ms`, `glide_ms`) : **mode** polyphonique / mono (la nouvelle note repart) / mono legato (la voix continue et change de hauteur, **glissando** 0 à 2 000 ms) ; **limite de voix** 1 à 256 (défaut 64 ; raccourcis 64 / 128 / 256 ; plafond du moteur 256, 64 emplacements de fondu ; tampons de streaming ~42 Mo par instance) ; **vol de voix** : plus ancienne, plus faible (niveau courant = vélocité × gains × enveloppe), garder les graves (vole la plus aiguë), garder les aigus ; avec « garder les graves/aigus », une nouvelle note qui est elle-même la plus extrême est abandonnée ; **même touche rejouée** : empiler (défaut) ou couper l'ancienne ; **durée du fondu de coupure** 1 à 200 ms (défaut 3 ms), commune aux voix volées, coupées et au mono. - **Réponse de vélocité et fondu entre couches (2026-10-12, jalon 5)** : bouton « Vélocité... » de la matrice → fenêtre flottante (`VelocityPanel`). **Courbe de l'instrument** (`core/VelocityResponse.h`) : `shape` ∈ [-1,1] (sortie = entrée^(2^(3·shape)) ; < 0 douce, > 0 dure) + préréglages (linéaire, douce, très douce, dure, très dure) **et/ou points** (max 16, espacés d'au moins 0,02, y croissants) : avec des points la courbe passe par eux en interpolation monotone de Fritsch-Carlson (jamais de dépassement ni de recul) et la forme est ignorée ; table de 128 entrées pour l'audio, **bypass exact quand la courbe est linéaire**. Appliquée AVANT le choix des couches et le volume (la vélocité des zones de relâchement est celle déjà remappée). **Fondu entre couches** : les zones d'une même *famille* (mêmes notes, même Groupe, même déclenchement) forment des couches ; **largeur automatique** par instrument (0 = commutation franche, jusqu'à 64 vélocités ; fondu centré sur la frontière entre couches jointives, demi-largeur bornée par la moitié de chaque couche voisine) **et** fondu sur les **chevauchements explicites** (partiels : sur toute la zone commune) ; **couches imbriquées ou de même étendue : elles jouent toutes à pleine puissance** (empilement, décision de l'utilisateur ; ce n'est plus « la première gagne » comme avant). Une note déclenche donc plusieurs voix (jusqu'à 16 zones) : le fondu double le nombre de voix aux frontières. La matrice dessine en bandes claires la partie des couches qui joue en fondu au-delà de leur plage. - **Matrice notes × vélocité (2026-10-12, jalon 5, premier jet)** : vue **Mapping** (décision de l'utilisateur, 2026-10-12 : **il n'y a plus que deux vues, Mapping et Probe** ; la vue Sampler est supprimée, tout y est regroupé) : en haut Load sample / Importer / mode / liste (afficher-masquer) / état, puis note racine / supprimer ; à gauche la liste des zones (rétractable) et le panneau « Chargé en mémoire » ; au centre la matrice puis l'enveloppe ; les potards (gain, accordage) en bas. Sélection partagée avec la liste. **Annulation par différences** (`core/InstrumentEdit.h`) : une entrée par geste, ne garde que les zones modifiées (copie complète seulement si le nombre de zones change). Zones de saisie des bords : 24 px de large ; un rectangle étroit garde son tiers central pour le déplacement (zoomer pour le saisir).
  - **Non fait** : couches de vélocité en fondu enchaîné, courbe de vélocité de l'instrument, aimantation/grille, création d'une zone par glisser-déposer d'un fichier sur la matrice (spec §Zone clavier), recherche/filtre dans la matrice, déplacement à la flèche du clavier.
- **Streaming disque (2026-10-12, jalon 4, premier jet)** : réglage **par instrument** (sauvegardé avec lui : `stream_from_disk`, `preload_kb`), accessible en cours d'usage dans le panneau « Chargé en mémoire » (case + préchargement 32 Ko à 4 Mo, **128 Ko par sample par défaut** : décision de l'utilisateur, remplace les « 200-500 ms réglables dans les réglages généraux » de la spec §22). Tout-RAM reste le défaut et reste disponible. Mécanique (`core/.../DiskStreamer.h`) : `SampleData` garde `frames` = longueur du fichier et `residentFrames` = ce qui est en mémoire ; un thread disque (`std::thread`, sondage 1 ms) remplit un tampon circulaire de 16 384 frames par voix (80 emplacements = 64 voix + 16 fondus, ~10,5 Mo alloués au premier instrument streamé) ; l'audio lit d'abord la partie résidente puis le tampon, ne fait jamais de disque ni d'allocation ; protocole sans verrou (compteur de demande impair/pair, `ready`, `writePos`/`readPos` atomiques, paramètres de demande en double exemplaire). **Zones en boucle** : tout ce qui précède la fin de boucle (+4) reste en mémoire, jamais de flux. **Sous-alimentation** : si le disque n'a pas livré à temps, la voix s'éteint en fondu court (3 ms) sur ce qui est disponible, l'incident est compté et affiché dans la ligne d'état (« streaming : N coupure(s) »). Estimation de mémoire et chargement partagent `residentFramesNeeded` (testé : l'estimation égale la mémoire réelle de l'instrument construit + tampons). Rendu streamé **identique bit à bit** au rendu tout-RAM (test). Limite de zones lues dans un état : relevée de 4 096 à 32 768 (un piano la dépassait).

  - **Non fait / à valider** : mesure sur disque réel (HDD, 64 voix) ; priorité du thread disque ; chemins > 1 024 octets (chargés en entier) ; tampon 16 384 frames pour des transpositions très hautes (au-delà de ~4× la vitesse, sous-alimentation possible) ; matrice et autres éléments de l'ordre « Ensuite ».

## Palier 1 — jalon 2 : enveloppe d'amplitude (validé)

- **Décisions de l'utilisateur (2026-10-12)** : **un seul Hold**, entre l'attaque et le decay (le second de la roadmap est abandonné) ; affichage **graphique** de la courbe où l'on déplace les temps ET les formes ; l'enveloppe **agit aussi en one-shot, Note Off ignoré** ; des **réglages prédéfinis pour percussions** (attaque seule, ou attaque + hold + decay), les segments étant activables/désactivables un par un.
- **Segments** : Délai (spec : retarde le début de l'attaque, pas le sample), Attaque, Hold, Decay, niveau de Sustain, Relâchement. Chacun a un interrupteur ; désactivé = sauté ; tout désactivé = enveloppe neutre (gain 1, pas silence). Temps 0 à 10 s (relâchement ≥ 1 ms). Défaut : tout neutre, relâchement actif 50 ms (comportement du jalon 1).
- **Formes** : linéaire ; paramétrique `shape` ∈ [−1, 1] (g(x) = x^(2^(−3·shape)), >0 convexe) ; **linéaire en dB** (plancher −60 dB, ramené à 0 exactement ; decay vers un sustain > 0 : dB exactement linéaire). Tables de 256 points précalculées par zone hors temps réel (`EnvelopeRuntime`) ; une valeur par échantillon (`EnvelopeRunner`), sans allocation.
- **Comportements voulus** : decay vers sustain 0 → la voix est libérée dès l'enveloppe à zéro (utile pour couper la queue d'un son) ; relâchement désactivé en mode boucle → fondu de secours de 2 ms (anti-clic) ; Note Off pendant l'attaque → relâchement depuis le niveau atteint, sans saut.
- **Édition en direct** : changer un réglage de zone republie l'instrument ; **les voix qui jouent continuent** (même indice de zone et même sample) avec les nouveaux réglages (enveloppe, hauteur, gain). Un autre sample arrête les voix.
- **Valeurs prédéfinies** (`EnvelopePreset`, à affiner à l'oreille) : Tenu = tout neutre ; Percussion attaque seule = attaque 3 ms forme 0,4, relâchement off ; Percussion attaque + hold + decay = attaque 2 ms, hold 20 ms, decay 300 ms forme 0,6 vers 0, relâchement off. Ce sont des configurations de la même enveloppe, pas un autre type : le futur gestionnaire de presets (palier 6) pourra les réutiliser.
- **Format** : schéma d'état **v4** ; `release_ms` des zones du jalon 1 est relu comme enveloppe (relâchement seul). Les chemins du v3 se rechargent.
- **Éditeur graphique** (`EnvelopeEditor`, adaptateur) : 5 colonnes (Délai, Attaque, Hold, Decay, Relâchement) + plateau de sustain ; glisser un nœud horizontalement = temps (échelle cubique : précision sur les temps courts), le nœud de fin du decay aussi verticalement = niveau de sustain ; la poignée au milieu d'une courbe, glissée verticalement = forme ; **double-clic sur la poignée = forme linéaire ; appui long ou clic droit = bascule dB** (poignée creuse) ; interrupteurs par segment et menu de réglages prédéfinis. Zones de saisie de 44 px (tactile).
- **Fenêtre** : deux vues, **Sampler** (chargement, mode, note racine, enveloppe, potards) et **Probe** (l'ancien diagnostic hôte) ; bouton en haut à droite. Le relâchement n'a plus de curseur dédié (il est dans l'enveloppe).
- **Limites** : l'enveloppe est par zone (l'héritage par Groupe de la spec viendra avec les Groupes) ; les modifications de zone ne passent pas par l'annulation (comme avant) ; pas de lecture de la forme au clavier ; l'affichage ne montre pas la durée réelle du sample ni le sustain en temps.
- **Validation (2026-10-12)** : testé par l'utilisateur sous Windows et Linux, souris et tactile : fonctionne.
- **Coût** : `neptune_perf_callback` (64 voix en boucle, enveloppe neutre) : environ **6,5 % du budget temps réel** (5 % au jalon 1) ; l'enveloppe ajoute ~1,5 point à cette charge, sans optimisation.

Au tactile le réglage fin passe par la modale. Ctrl/Cmd+Z annule, Ctrl/Cmd+Maj+Z ou Ctrl+Y rétablit.
- **Conséquence à ne pas oublier** : le clic droit ouvre maintenant la modale, pas un menu. Quand viendront « Apprendre » (MIDI Learn, palier 3) et « Ajouter à la Façade » (palier 2), leurs entrées devront vivre dans la modale (ou un menu à part) : à décider alors.

Tous les réglages sont dans `KnobConfig` : seule la sensibilité du glisser (0,006 par pixel) vient de la maquette ; **les autres valeurs sont des points de départ à affiner à l'usage** : réglage fin ×0,1, appui long 500 ms, tolérance de mouvement 3 px (souris) / 8 px (doigt), double-tap 400 ms et 6 / 24 px, pas de molette 0,02 (fin 0,002), pas de flèche 0,01 (fin 0,001, PageUp/Down 0,1 ; paramètres discrets : un pas / un dixième). **Zone tactile minimale : 44 px** (`minTouchTarget`, valeur proposée et confirmée, pas une norme vérifiée).

Annuler/rétablir ne sont **pas** des événements d'automation : l'hôte relit les valeurs (même mécanisme qu'au chargement d'un état) ; il n'enregistre donc pas l'annulation comme un geste d'automation.

- **Vérification** : adaptateur contrôlé à la syntaxe contre les vrais en-têtes JUCE 8.0.11 (4 fichiers, sans erreur) ; la CI le compile en entier. Validé par l'utilisateur dans Reaper : Windows en tactile, Linux (après correction de la disposition, piège 7).

## Profils Live/Studio (mécanisme, palier 0)

- **Aucun traitement n'a encore de variante** : le mécanisme est en place, `Engine::profile()` est lu à chaque bloc, rien ne change à l'oreille. Les futurs traitements à latence (oversampling, look-ahead, convolution, time-stretch) liront `Engine::profile()`.
- **Réglage global par processus** (`Profile.h`, `SharedProfile::process()`) : toutes les instances du plugin chargées dans le même processus Reaper le partagent (variable statique du `.clap`, lecture sans verrou). La **première** instance l'initialise depuis `performance_profile` de `settings.json` ; les suivantes ne l'écrasent pas.
- **Décision (2026-10-11) : la bascule n'est jamais réécrite dans `settings.json`** ; elle vaut jusqu'à la fermeture du processus. `settings.json` ne change qu'à la main.
- **Verrou par instance** (`InstanceProfile`) : l'instance garde son profil même si le global bascule. **Décision : le verrou est sauvegardé dans le projet** (`"profile_lock": "live"|"studio"`, absent = non verrouillé). Une valeur illisible est lue comme « non verrouillé ».
- **Schéma d'état passé en v2** (le seul changement : ce champ facultatif). Migration v1→v2 enregistrée (aucune transformation : un document v1 est un v2 valide). Conséquence : **une version plus ancienne du plugin refuse les projets enregistrés par celle-ci** (« état trop récent », rien n'est chargé).
- **Interface** : la fenêtre de sonde a deux boutons (basculer le profil global, verrouiller/déverrouiller l'instance) et une ligne d'état. Pas de menu final.
- **Projet marqué modifié** : constaté dans Reaper (2026-10-12) que le changement de verrou ne marquait pas le projet ; corrigé en déclarant un changement d'état hors paramètres (`withNonParameterStateChanged`, que le wrapper traduit en `mark_dirty` de CLAP ; vérifié dans le code de clap-juce-extensions et de JUCE 8.0.11). La bascule du profil **global** ne marque rien : elle n'est pas dans le projet (décision). **Validé dans Reaper par l'utilisateur** (2026-10-12), ainsi que la bascule et le verrou à deux instances et la relecture du verrou après réouverture du projet.

## Format d'état JSON (point 3) : décisions et suite

- Chargement **tout ou rien** : document invalide ou plus récent → refus, aucun paramètre modifié. Plus ancien → migration silencieuse (`registeredMigrations()` : un saut n → n+1 par version ; un test garde-fou échoue si on monte `currentSchemaVersion` sans l'enregistrer).
- Toutes les valeurs sont sauvegardées (pas seulement celles ≠ défaut) : changer un défaut plus tard ne modifie pas un preset existant. Un paramètre absent du fichier revient à son défaut au chargement.
- À faire quand les samples existeront (palier 1/6) : chemins de samples (relatif au preset, absolu, recherche par nom, relocalisation — spec §20), export ZIP portable, presse-papier = sous-arbre JSON, extensions `.neptunepreset` / `.neptunecache`.

## Pistes parallèles (2026-10-14, à valider dans Reaper)

- **Décisions de l'utilisateur** : pool propre de **32** pistes parallèles (elles ne prennent pas les 16 pistes génératrices) ; **somme toujours en fin de chaîne du parent** (après son pan ; pas de point de sommation réglable pour l'instant) ; **solo « en place »** (le parent reste actif et alimente la parallèle, sans être entendu) ; mêmes paramètres d'hôte qu'une piste.
- **Modèle** (`mixer::ParallelSettings`, état schéma **v8**, clé `parallels`) : active, **parent** (0..15 piste, 16..47 piste parallèle), **point de captation** dans la chaîne du parent (les 4 points des envois ; défaut post-pan), une bande complète (nom, couleur, 8 inserts, 8 envois, sortie directe, loi de pan, fader, pan, mute, solo). « Sortie principale activée » = se somme dans le parent. Structure en arbre : une parallèle ne capte que la chaîne de son parent direct ; boucles, parents inactifs ou inexistants sont détachés à la lecture (`fixParallels`) et jamais traités par le moteur.
- **Moteur** : un parent traite son instrument, ses inserts, son fader et son pan, puis ses parallèles (récursif, tampons par profondeur jusqu'à 32) captent leur point, passent par leurs inserts / fader / pan, et se somment dans le signal propre du parent **avant** ses envois, sa sortie directe et sa sortie principale. Le vu-mètre d'une piste montre le total (elle + ses parallèles). Une piste silencieuse n'est ignorée que si ses parallèles le sont aussi (queues d'inserts préservées). Pistes et parallèles forment le même domaine de solo ; le solo d'une piste garde ses parallèles audibles.
- **Paramètres hôte** (`mixer::parallelParam`, ids `5000 + 100.p + offset`) : volume, pan, mute, solo, 8 bypass d'inserts, 8 niveaux d'envoi (26 par parallèle, 832 au total).
- **Interface** : bouton « P » sur chaque piste et chaque parallèle (à côté de M et S) : crée une parallèle juste à droite. La bande parallèle est visuellement distincte (fond de l'application, bord d'accent à gauche), son en-tête indique sa parenté (« P2 <1 »), un menu règle le point de captation, « × » la supprime avec ses descendants (confirmation si elle a du contenu). **Repliement** : les filles d'une parallèle sont masquées par défaut (bouton ▸n / ▾n), elles restent actives dans le moteur. La rangée des pistes défile horizontalement. Retirer une piste retire ses parallèles. Ajouter, retirer ou modifier le parent d'une parallèle vide l'historique d'annulation.
- **Suivi du volume du parent** (décidé le 2026-10-14) : option par parallèle (fenêtre « Routage ») : le gain de fader du parent s'applique aussi à la parallèle (fondu sur le bloc ; le mute du parent la coupe aussi). **Effet seulement pour une captation avant le fader** (points 0 et 1) : après le fader, le signal contient déjà le volume du parent. Les petites-filles suivent le fader de leur parent direct.
- **Décisions** : point de sommation fixe en fin de chaîne (à revoir seulement si le besoin apparaît) ; **le parent d'une parallèle ne change jamais après sa création**.
- **Non fait** : copier-coller d'une parallèle, déplacement par glisser-déposer, repliement mémorisé dans le projet.
- **Point à valider** : profondeur maximale = 32 (le pool) ; le total d'une piste (vu-mètre) inclut ses parallèles.

## Synthé soustractif complet (2026-10-14, à valider dans Reaper)

- **Structure** (spec §2) : 3 oscillateurs + sous-oscillateur + bruit -> mixeur des 5 sources (niveau automatisable, mute, pan) -> 2 filtres (série / parallèle avec balance, chacun avec son enveloppe) -> enveloppe de volume ; enveloppe de pitch dédiée (profondeur ±48 demi-tons automatisable). Polyphonie poly / mono / legato, vol de voix, glissando comme avant.
- **Oscillateurs** : catalogue de **32 formes** (`WaveCatalog.h`), 3 catégories (numérique 10, style analogique 8, complexe 14), noms génériques (« Ladder saw »...). Sinus, triangle, dent de scie, carré et impulsion (largeur automatisable) sont **analytiques à bande limitée** (PolyBLEP / PolyBLAMP) ; les 27 autres sont des **tables d'onde à bande limitée** (une table par octave, 10 niveaux, construites une fois par FFT). Mesuré : aucune forme du catalogue ne dépasse 0,4 % d'énergie hors harmoniques à 1,5 kHz. Réglages par oscillateur : forme, octave, demi-ton, fine tune (automatisable), **unisson 1 à 8 voix** (détune automatisable 0..100 cents, écartement stéréo, courbe linéaire ou « supersaw » en |x|^1,65), retrigger / phase libre, phase de départ, **synchro dure** (oscillateurs 2 et 3 sur le 1, avec correction PolyBLEP à l'instant de la resynchronisation pour les formes à marche : dent de scie, carré, impulsion ; sans correction pour les autres formes).
- **Sous-oscillateur** : sinus / triangle / carré, -1 ou -2 octaves. **Bruit** : blanc ou rose.
- **Paramètres automatisables** (15 par piste, `mixer::synthParam`, ids `1000 + 100.t + 40..54`) : niveaux des 5 sources, fine tune x3, largeur d'impulsion x3, détune d'unisson x3, profondeur de l'enveloppe de pitch ; plus ceux de l'instrument : gain, accordage, coupure et résonance des 2 filtres. Le reste (formes, enveloppes, routage, polyphonie...) est enregistré dans le projet (`SynthDescription`, JSON) et annulable.
- **Interface** : vue Synthé en 3 pages (oscillateurs + sous-osc + bruit ; filtres ; enveloppes + voix), **explorateur de formes** (dalle filtrable par catégorie et par texte, aperçu dessiné de chaque forme), clavier à l'écran. Les potards du bas ne montrent plus que gain et accordage pour un synthé.
- **Coût** (outil de performance, 256 échantillons) : 16 voix à 1 oscillateur ~2,5 % du budget ; 64 voix ~10 % ; **16 voix avec unisson 8 + 2 filtres ~9 %, 64 voix ~38 %** (pire cas).
- **Non fait** : modulation d'un oscillateur par un autre (FM, anneau), explorateur : pas de favoris ; synchro dure sans correction sur les tables d'onde ; pas de preset de son ; les formes « complexes » sont des spectres fixes (pas de table animée).
- **Points à valider à l'oreille** : niveau relatif des sources (somme de plusieurs sources + unisson : peut dépasser le niveau d'une voix seule), courbe supersaw, noms et contenu des formes du catalogue.

## Inserts et premier plugin stock : l'Utilitaire (2026-10-14, à valider dans Reaper)

- **Architecture** (cœur portable, sans JUCE) : `StockModule.h` (un module = DSP + déclaration de ses paramètres propres, identifiants >= 100), `ModuleRunner` (ce que tous les modules ont en commun : trim d'entrée / de sortie, mix, bypass, lissage ; possède le `ParameterSet` du module), `InsertInstance` (un module posé sur un emplacement), registre `availableModules()` / `createInsert()`. `UtilityModule.h` : l'Utilitaire (voir spec §8). Deux adaptateurs : l'insert de Neptune (`Engine`, `NeptuneProcessor`) et le plugin CLAP séparé (`MoussaillonPlugin`). L'interface (`UtilityEditor`, `NeptuneKnob`, `KnobModal`) ne connaît que `ParamHost` (jeu de paramètres + gestes d'édition).
- **Moteur** : 8 emplacements par piste, par bus et sur le Master. Ordre : instrument -> inserts -> fader -> pan ; bus : somme -> inserts -> fader ; master : somme -> trim -> inserts -> fader -> pan -> mono. Les points de captation des envois 0 (pré-inserts) et 1 (post-inserts / pré-fader) sont maintenant distincts. Le bypass d'un emplacement est un **paramètre de l'hôte** (pistes : `kInsertBypass` existant ; bus : `3000 + 100.b + 10..17` ; master : ids 7..14). Remise au thread audio par `HandoffSlot`. Les modules ne sont traités que s'ils sont présents ; un module contourné et fondu terminé n'est plus calculé.
- **Paramètres des inserts : NON exposés à l'hôte** (seulement le bypass). Ils sont enregistrés dans le projet (schéma **v7**, `inserts` dans chaque bande et dans le master), annulables (même historique), mais pas automatisables. À reprendre avec la réflexion sur l'automation (voir `spec-modules.md` §7).
- **Interface** : dans chaque bande (pistes, bus, master) 4 lignes d'inserts visibles sur 8 (molette ou flèche pour les 4 suivantes) ; vide = « + » (menu des modules), rempli = clic pour éditer, clic droit : ouvrir / bypass / retirer. L'éditeur s'ouvre en fenêtre superposée (titre, bypass de l'emplacement, fermer). Les bandes s'adaptent à la hauteur disponible (300 à 360 px) ; fenêtre par défaut 1160 x 960. Ajouter ou retirer un insert vide l'historique d'annulation.
- **Plugin séparé** : cible `Moussaillon` (CLAP `com.tournedosrossini.moussaillon`, nom provisoire ; en-tête « MOUSSAILLON / UTILITY · FLIBUSTE SUITE » en orange comme la maquette de Neptune), état JSON `moussaillon-state`, thème / langue / contraste lus dans le même `settings.json` que Neptune. Compilé, validé par `clap-validator` et archivé par la CI (`Moussaillon-<OS>`).
- **Non fait** : copier-coller de module entre emplacements, déplacement par glisser-déposer des inserts, presets / A/B, aide en ligne, redimensionnement par la poignée de coin NOVA (la fenêtre est redimensionnable par l'hôte), goniomètre, latence PDC (aucun module n'en a pour l'instant).
- **Points à confirmer** : loi du pan double (puissance constante, indépendante de la loi choisie pour le pan simple) ; Mid = (L+R)/2 ; plage des trims ±24 dB.

## Type de piste « Entrée audio » (2026-10-17, à valider dans Reaper)

Décisions de l'utilisateur : le signal vient des envois des autres pistes ET de l'entrée audio de l'hôte ; ordre de traitement sans cycle ; vue = bande de mixeur + liste des sources.

- **Cœur** (`TrackType::AudioIn` = 4, JSON `"audio_in"`) : la piste n'a pas d'instrument ; son signal brut = envois reçus + entrée de l'hôte (si `StripSettings::hostInput`, vrai par défaut, JSON `host_input`), multiplié par le gain de la piste (le potard « gain » de l'instrument sert de trim). Ensuite inserts, fader, pan, envois, pistes parallèles comme toute piste. Pas de notes (ignorées).
- **Destination d'un envoi** : 1..16 = bus (inchangé) ; `mixer::firstTrackDestination + n` (17 + n, n = indice de la piste) = piste Entrée audio. Validité jugée au traitement : la cible doit être active et de type Entrée audio, jamais la piste elle-même (pistes parallèles comprises : leur racine), jamais depuis un bus ; une Entrée audio n'envoie qu'à une Entrée audio d'indice supérieur. Le moteur traite d'abord les pistes ordinaires, puis les Entrées audio dans l'ordre (types lus une fois par bloc) : aucune boucle possible. Les envois vers une piste qui n'est pas (ou plus) une Entrée audio sont ignorés, pas supprimés.
- **Entrée de l'hôte** : le plugin déclare maintenant un port d'entrée stéréo « Input » (**change la déclaration CLAP : à vérifier dans Reaper, notamment le routage et que le validateur reste vert**). `processBlock` la copie avant que le moteur n'écrive les sorties (les canaux 0 et 1 du tampon JUCE sont aussi la première sortie), `Engine::setHostInput` ne vaut que pour l'appel suivant à `process`. Copie limitée à 8192 échantillons (ou la taille de bloc annoncée) : au-delà, pas d'entrée pour ce bloc.
- **Interface** : la pastille de type du mixeur propose « Entrée audio » (abréviation IN) ; la vue Mapping d'une telle piste est remplacée par `AudioInView` (interrupteur « Entrée audio de l'hôte », liste des envois reçus avec leur niveau). Le menu de destination des envois (panneau de routage d'une piste) propose « Entrée audio, piste N » pour les pistes de ce type (grisé si impossible). Les potards du bas restent ceux de l'instrument (seul le gain agit).
- **Pas fait** : enregistrement audio direct dans le Sampler (spec §21), sidechain, sélection d'un sous-ensemble de canaux de l'entrée de l'hôte (stéréo ou mono dupliqué), destination « Entrée audio » pour la sortie principale d'une piste (envois seulement, comme la spec).
- **Test instable corrigé au passage** : `organ engine: any block size gives the same sound` (tolérance 10 % trop juste à cause des phases aléatoires du Leslie, passée à 25 %).

## Orgue : clic des touches (2026-10-17, à écouter dans Reaper)

Décisions de l'utilisateur : seulement le key click pour l'instant (diaphonie, clavier à l'écran au choix, rayons et micros du Leslie restent à faire) ; réglages dans la description de l'orgue (page Réglages), enregistrés avec la piste, non automatisables.

- `OrganDescription::clickLevel` (0..100 %, 50 = setBfree), `clickLength` (25..400 %, 100 = setBfree : multiplie la durée du bruit, 8 à 40 échantillons à 22,05 kHz d'origine), `clickRelease` (0..100 %, 0 = relâchement linéaire de setBfree ; > 0 : le relâchement clique aussi). JSON `key_click`. Avec les valeurs d'origine, `nb3_create_full` reçoit NULL : setBfree tel quel.
- Fixé à la construction (les enveloppes sont calculées une fois dans `initToneGenerator`) : comme l'accord, un changement reconstruit l'orgue (`OrganVoices::requestBuild`) ; l'interface applique au relâchement du curseur. Niveau = atténuation aléatoire des contacts : un niveau plus haut donne un attaque plus bruitée (début moins fort), pas « plus de clic » au sens du volume.
- Interface : page Réglages, boîte « Clic des touches » (3 curseurs, double-clic = valeur d'origine). Mesure (24 touches, énergie des 128 premiers échantillons) : niveau 0 -> 100 divise l'énergie par ~2, durée 25 % -> 400 % la multiplie par ~3 : l'effet est réel, le goût reste à juger à l'oreille.
- Pas repris : modèle d'attaque (cosinus, linéaire, étagé), longueur minimale séparée.

Décaleur à deux têtes de lecture à fenêtres de Hann (somme constante), sur un court tampon alimenté par la lecture de la ligne **avancée d'un demi-grain** (le retard moyen du décaleur est retranché du temps de la ligne ; si le temps est plus court, le retard réel est le minimum possible). Placé avant les filtres et dans la boucle de feedback : chaque répétition est décalée de nouveau (shimmer). Hauteur lissée sur 20 ms ; fondu de 20 ms avec le chemin direct à l'activation et à la désactivation ; quand PITCH vaut 0 le décaleur n'est pas calculé (aucun filtre en peigne, aucun coût).
- **Interface** : potard PITCH (suit la ligne choisie) entre FEEDBACK et MIX ; qualité du pitch dans SETTINGS ; aides `hlp.dl_pitch` et `hlp.dl_pitchquality`. Preset d'usine « Shimmer Pad » ajouté.
- **Tests** : +12, -12 et +7 demi-tons donnent la bonne fréquence (mesure par fenêtres de 20 ms : les sauts de phase à chaque grain interdisent une mesure cohérente sur une longue durée), l'écho décalé reste sur le temps de la ligne, le feedback décalé monte à chaque répétition et reste borné, les deux qualités.
- **Limites connues** : un décaleur à grains croisés colore les sons tonaux (modulation d'amplitude légère à la cadence des grains) ; le passage d'un temps long à un temps court avec PITCH actif fait glisser la hauteur (Glide) comme tout changement de temps ; coût CPU de 8 lignes décalées non mesuré.

### Delay : matrice TAPS (2026-10-20, à valider dans Reaper)

- Page TAPS = tableau des huit lignes (numéro, ON, SOLO, TEMPS ou DIVISION, NIVEAU, PAN, DÉCALAGE D, FEEDBACK, PITCH, COUPE-BAS, COUPE-HAUT, INVERSION, PROFONDEUR et VITESSE DE MOD). Un clic sur une ligne la choisit ; un clic sur un interrupteur le bascule ; glisser une valeur vers le haut ou le bas la règle (160 px = toute la plage, Maj = dix fois plus fin) ; la molette aussi ; un double-clic remet la valeur par défaut. Les valeurs neutres sont plus discrètes.
- Dessous : les potards de la ligne choisie (coupe-bas, coupe-haut, profondeur et vitesse de modulation, décalage droit), INVERSION, **COPIER / COLLER / REMETTRE** (la copie ne reprend pas l'état solo ; REMETTRE rend à la ligne ses valeurs d'usine, celles de sa position).
- Pas fait : simulation d'un coup d'entrée et courbe de ducking sur la page GLOBAL, changement de temps par fondu (Crossfade), sections de SETTINGS manquantes, loi de pan.

### Delay : retouches TAPS et simulation de la page GLOBAL (2026-10-20, à valider dans Reaper)

- **TAPS** : la matrice des huit lignes est plus haute (lignes de 40 px, texte plus gros) ; les potards de la ligne choisie, INVERSION, COPIER / COLLER / REMETTRE descendent en dessous.
- **GLOBAL** : simulation d'un coup d'entrée (`GlobalSim`) : un second module de delay à 16 kHz reçoit les mêmes réglages (y compris tempo, feedback global, ping-pong, routage, filtres, pitch, ducking) et traite un court coup de sinus à 1 kHz ; l'enveloppe des échos (gauche en haut, droite en bas) et la courbe de gain de ducking (bande du bas, 0 à -24 dB) sont tracées sur 1 à 6 s (le plus long premier écho x 3). Recalculée quand un réglage change, au plus dix fois par seconde. Les potards sont redescendus en deux rangées.

### Delay : changement de temps par fondu, fin du delay (2026-10-20, à écouter dans Reaper)

- **Crossfade** : réglage `timeMode` (id 113, Settings, non automatisable : Glide ou Crossfade). En Crossfade, un nouveau temps (écart > 2 échantillons) lance un fondu de l'ancien temps vers le nouveau, de la durée du réglage « glide » (renommé temps de glissement / fondu), sans variation de hauteur ; un changement arrivé pendant un fondu attend sa fin. Le décalage de hauteur et la modulation suivent le même mélange. Tests : mode par défaut, sinus continu pendant le changement (borné), écho au nouveau temps une fois le fondu terminé.
- **Décision de l'utilisateur** : pas de loi de pan (le module reçoit toujours du stéréo ; le panoramique reste une balance). **Le delay est donc terminé** pour ce qui était prévu : DSP à huit lignes, pitch, matrice TAPS, simulation GLOBAL, Settings propres au delay (temps de glissement, changement de temps, limiteur de sécurité, qualité du pitch).
- **Reste, commun à tous les plugins de la suite** : sections AUDIO / DSP, METERING, INTERACTION de SETTINGS (point 4 de la liste), vu-mètres complets (VU, EBU, LRA), tests tactiles sous Windows. Hors delay : chorus, Hammond, migration de La Flèche (faite), barre LRA du compresseur.

- **Changement d'ordre** dans `ModuleRunner` : `params_` est déclaré avant `module_` (le module, et son thread qui lit les paramètres, est détruit le premier).
- **Interface** `NovaConvolutionEditor` : pages IR (forme d'onde / spectre avec marqueurs B et E déplaçables, choix du fichier, 5 potards de retouche, mode d'entrée, rognage auto, longueur auto, inversion, normalisation), TONE (pré-délai, largeur, mix, sortie, EQ), LEVELS (crête, RMS, LUFS), SETTINGS. 6 presets d'usine (réglages de la voie traitée seulement, pas de fichier d'IR).
- **À valider** : le chargement par le sélecteur de fichier, le glisser des marqueurs B/E, le rendu avec une vraie IR (cabine, salle), l'insert dans Neptune (sauvegarde / rechargement du projet avec le chemin du fichier).
- **Suite (2026-10-23)** : l'EQ de la page TONE est un égaliseur graphique (`EqView` : courbe de réponse calculée par `ParametricEQ::responseDb`, 5 poignées, molette = Q ou pente, double-clic = marche/arrêt). Formats d'IR : WAV / Wave64 par le lecteur du moteur (jusqu'à 8 canaux, vraie stéréo à 4), AIFF / FLAC / Opus par `loadSampleFile` (mono ou stéréo seulement). Glisser-déposer d'un fichier sur la fenêtre. Le changement de fichier est annulable : `ParamHost::uiEditText` (commande `SnapshotCommand<std::string>` dans l'historique du plugin ou de Neptune).
- **Pas fait** : EQ avant la convolution (décision de l'utilisateur : on pose un égaliseur en insert avant), mode « économie » à latence déclarée (inutile tant que la latence est nulle).


## La Façade (2026-10-23 à 25, validée par l'utilisateur sous Linux sauf mention)
- **Principe** : onglet FAÇADE de Neptune, une Façade par piste, stockée dans `StripSettings::facade` (donc dans le projet, annulable par `uiEditTrack`). Cœur : `core/.../Facade.h/.cpp` (modèle, JSON, bornes, outils d'alignement, zones, cercle), `FacadeTransfer.h` (rebranchement sur une autre piste, chemins d'images), `StylePack.h` (packs de styles), `MidiSend.h` ; interface : `adapter-juce/src/FacadeView.cpp` (Canvas, Picker, TextPrompt, HelpPanel, StylePanel, NotchPanel), `StyleLibrary.h`, `FacadeBundle.h`, `FacadeExamples.h`, `FacadeSpec.h` (généré par `scripts/gen_facade_spec_header.py` depuis `docs/specification-styles-facade.md` et `docs/style-pack-specification.en.md` : à relancer quand ces documents changent).
- **Widgets** : potard, bouton, étiquette, menu, action (instantané / annulation générale), courbe de vélocité (courbe d'entrée de la piste, `StripSettings::velocityCurve`, tous types de piste), zone (conteneur avec rangement ligne / colonne / matrice / cercle), clavier (par canal MIDI, notes allumées par piste et par canal : `Engine::heldChannelWord`), curseur (tirant), voyant, touche Set (pistons programmables), message MIDI (vers Neptune par une file vers `processBlock`, vers l'hôte par `addOutboundEventsToQueue` : **sortie hôte validée par l'utilisateur**), vumètre. Potards et curseurs : crans personnalisés et inversion.
- **Styles d'images** : PNG / JPG / SVG ; packs `.neptunestyle` (zip, lus sur place) installés dans `<dossier de configuration>/styles` ; références `pack:<id>!<entrée>` ; couleurs du thème dans les SVG (`{{accent}}`...) ; spécification complète en `docs/` (format 2).
- **Façade portable** : `.neptunefacade` (zip : `facade.json`, `assets/`, `packs/`), rebranchement des paramètres sur la piste cible, bouton « Relocaliser… ». Elle entre aussi dans l'export de piste complète (ci-dessous).
- **Façade dans les presets de piste (2026-10-25, à valider dans Reaper)** : `Preset::facade` (objet JSON `{"track":n,"facade":{...}}`, absent si la piste n'a pas de Façade). Enregistrer / écraser un preset de synthé, FM ou orgue dans Neptune y met la Façade de la piste (`NeptuneProcessor::attachFacade`) ; les images sont copiées une fois dans `<bibliothèque>/facade-assets/` sous un nom à empreinte (`asset:<nom>`), les packs de styles dans `facade-assets/packs/`. Charger un preset qui a une Façade remplace celle de la piste (même entrée d'annulation que le preset) ; sans Façade, celle de la piste reste. Les autres plugins conservent le champ sans l'utiliser. Les `.flibank` emportent les images et packs (`facade-assets/` dans le zip) ; un `.flipreset` isolé n'emporte que la référence (images à relocaliser). Code : `FacadeBundle.h` (`storeInFolder`, `restoreFromFolder`, `referencedFiles`).
- **Export de piste complète `.neptunetrack` (2026-10-25, à valider dans Reaper)** : menu du type de piste (bouton de type en haut de la bande d'une piste du Mixeur) -> « Exporter cette piste... » / « Importer une piste dans une nouvelle piste... ». Zip : `track.json` (`TrackExport.h/.cpp` : `{"format":1,"track":n,"state":{piste},"params":{id:valeur}}`, l'état de la piste réutilise la sérialisation du mixeur), `samples/` (fichiers audio des zones du Sampler et IR de la convolution, chemins réécrits `asset:samples/...`), `assets/` et `packs/` (Façade, même disposition que `.neptunefacade`). Contenu : type, instrument ou patch (synthé / FM / orgue), inserts avec leurs valeurs, matrice de modulation, Façade, courbe de vélocité, bande (nom, routage, envois) et valeurs des réglages de la piste (`ownedParams`). À l'import (`NeptuneProcessor::uiImportTrack`) : nouvelle piste (`uiAddTrack`), identifiants rebranchés (`remapTo` : réglages, destinations de modulation, liens de la Façade ; les destinations d'insert sont indépendantes de la piste), canal MIDI de la nouvelle piste conservé, fichiers extraits sous `<config>/imported-tracks/track-<empreinte>` (jamais écrasés), packs de styles absents installés, historique d'annulation vidé. Refus si les 16 pistes sont prises. Non fait : remplacer une piste existante, sends vers des bus (gardés tels quels), pistes parallèles de la piste. Code : `TrackBundle.h` (zip), `FacadeBundle.h` (`addEntries`, `extractEntries`, `resolveAssets` partagés avec `.neptunefacade`).
- **Preset global de Neptune `.neptuneset` (2026-10-25, à valider dans Reaper)** : bouton « Preset global » dans la rangée du bas de l'éditeur (à gauche de Annuler). Menu : Enregistrer comme preset global... (nom ; confirmation avant d'écraser), liste des presets (clic = charger, avec confirmation : **remplace tout** le mixeur et les valeurs, historique d'annulation vidé), Supprimer (corbeille du système), Ouvrir le dossier. Fichiers dans `<dossier de configuration>/GlobalPresets/`. Contenu : l'état du projet (`state::save`) sans identifiant d'instance, verrou de profil ni couche de contrôle (assignations CC / OSC : propres à la machine, elles restent). Zip : `state.json`, `assets/` et `packs/` (images et packs de styles de toutes les Façades, mêmes dispositions que `.neptunefacade`). **Les samples ne sont pas copiés** (chemins gardés, comme le projet) : un preset est donc portable entre machines seulement si les samples sont aux mêmes chemins. Cœur : `GlobalPreset.h/.cpp` ; adaptateur : `GlobalPresets.h`, `NeptuneProcessor::globalStateText / uiLoadGlobalState`, `NeptuneEditor::showGlobalPresetMenu`. Pas fait : recherche dans la liste (le menu est plat), changement par Program Change / Bank Select, version « portable » avec samples, ajout de pistes sans tout remplacer.
- **Limites / idées** : pas de découpe en neuf zones pour les rails ; pas de police dans un pack ; potard en deux couches et bande de 32 images coexistent (l'aiguille prime).

## Matrice de modulation (2026-10-25, lot 1, à valider dans Reaper)
- **Principe** : la modulation est un décalage VIVANT (`ParameterSet::modOffsetAt`, unités normalisées) qui s'ajoute à la valeur réglée sans la changer ; `effectiveAt` donne la valeur avec modulation. L'automation de l'hôte, les presets et l'annulation ne voient jamais la modulation.
- **Cœur** : `Modulation.h/.cpp` (modèle : 4 LFO, 4 enveloppes ADSR, routes source -> paramètre continu avec quantité signée et option « centrée » ; JSON ; `compile` résout les destinations en indices ; `Modulator` évalue par bloc). Sources : CC MIDI (canal ou tous), pitch bend, aftertouch de canal, macros, LFO, enveloppes (déclenchées par les notes de la piste). Stocké dans `StripSettings::modulation`.
- **Moteur** : `Engine::processChunk` remet à zéro les décalages du bloc précédent puis évalue chaque piste active ; `Engine::param` et la lecture des réglages d'instrument du Sampler passent par `effectiveAt`.
- **Destinations couvertes par ce lot** : tout paramètre que le moteur lit à chaque bloc : bande (volume, pan, envois, mute...) et réglages d'instrument du Sampler (gain, accordage, filtres). **Pas encore** : réglages du synthé, du FM et de l'orgue (leurs valeurs passent par une description publiée depuis le thread de message, pas lues en direct par le thread audio) et paramètres des inserts. À traiter dans un lot suivant (décision à prendre : publication de patchs à cadence de contrôle, ou lecture directe des décalages dans les voix).
- **Interface** : onglet MOD (`ModView`), anneau de modulation sur les potards (`paintModulationRing`) de Neptune et de la Façade.
- **Suite (2026-10-25)** : les enveloppes de la matrice sont les enveloppes du projet (`EnvelopeDescription` : délai, attaque, maintien, decay, sustain, relâchement, courbes ; `EnvelopeRuntime`/`EnvelopeRunner` dans `Modulator`) et s'éditent avec le même `EnvelopeEditor` graphique (boutons ENV 1 à 4 dans l'onglet MOD). L'ancien format JSON (`a/d/s/r`) est encore lu. Filtres des listes de paramètres : `ParamGroups.h` classe chaque paramètre par portée (piste, parallèle, bus, Master, global) et famille d'après son nom ; `ParamFilterBar.h` (menu de portée + pastilles de familles) est utilisé par `ParamSearchPanel` (MOD) et par le sélecteur de la Façade. Vumètre de la Façade : sources piste/bus/piste parallèle/Master au choix et réduction de gain des compresseurs insérés (`MeterSource` dans `Facade.h`, `NeptuneProcessor::compressorReduction`). **À valider dans Reaper** : l'éditeur graphique d'enveloppe de l'onglet MOD, les filtres de listes, le vumètre de réduction de gain.
- **Lot 2 (2026-10-25) : modulation des modules en insert.** Constat vérifié par test : les paramètres **continus** du synthé, du FM et de l'orgue étaient déjà modulés (le moteur les lit par `Engine::param`, donc avec le décalage) ; les paramètres **par pas** (tirettes de l'orgue, vitesse de LFO FM, etc.) ne l'étaient pas ; ils le sont depuis le lot 3 (ci-dessous). Restait les inserts : leurs paramètres sont dans le jeu propre à chaque module. Une route vise un insert par `modulation::insertDest (emplacement, paramètre du module)` ; `Engine::addInsertOffset` résout la cible à chaque bloc (le module peut changer) et écrit le décalage dans le jeu du module ; `ModuleRunner` recopie les valeurs effectives dans un second jeu (`effective_`, même déclaration) que le module lit, tant qu'un décalage est non nul (l'interface, l'hôte et les presets ne voient que `params_`). Cadence = un décalage par bloc audio (option A) ; l'interpolation à l'intérieur du bloc et la modulation par note (option B) ne sont **pas** faites. Interface : la recherche de l'onglet MOD propose aussi les paramètres des inserts de la piste (`NeptuneProcessor::insertModulationTargets`). Le convolueur lit ses paramètres dans un autre thread, sur les valeurs de base (non modulées).
- **Lot 3 (2026-10-25) : paramètres par pas, interrupteurs et choix.** La matrice vise désormais tout paramètre `modulatable` et non caché, quel que soit son genre (`Kind::Continuous`, `Stepped`, `Toggle`, `Choice`) : dans `compile`, `Engine::addInsertOffset`, la recherche de l'onglet MOD (`ParamSearchPanel`) et `insertModulationTargets`. Le décalage est en unités normalisées de la plage : `effectiveAt` arrondit au pas le plus proche (tirette 0..8 : un LFO de quantité 0,5 va de 4 pas en dessous à 4 pas au-dessus de la valeur réglée, bornée à 0..8 ; un interrupteur passe à 1 quand la valeur effective atteint 0,5 ; un choix suit ses positions). La valeur réglée, l'automation de l'hôte et les presets ne voient toujours rien. `Track n Type` et `FM Algorithm` (sondes) sont marqués non modulables. Le moteur lisait déjà ces paramètres par `Engine::param` (valeur effective) : tirettes, pédalier, percussion, vibrato, Leslie, drive de l'orgue, LFO / bend / glide du FM, accordage en demi-tons, mute / solo / bypass d'insert. Test moteur : une route CC -> `Track 1 Mute` coupe la piste sans changer l'interrupteur réglé. **Non vérifié à l'écoute** : le changement de tirette ou de vitesse de Leslie en pleine note (clics éventuels), et l'anneau de modulation sur les commandes par pas (tirettes, boutons) qui n'ont pas de potard. Option B (modulation par note) : pas faite, seulement si besoin.
- **Échelle et courbe libre des liens de la Façade (2026-10-25)** : `Widget::scale` (0 échelle du paramètre, 1 linéaire en valeur, 2 logarithmique, 3 exponentielle) et `Widget::response` (une `VelocityCurve` croissante appliquée à la position avant l'échelle) ; `widgetNormalised` / `widgetPosition` (cœur, réciproque par dichotomie) ; seuls les paramètres continus sont concernés ; l'anneau de modulation passe par la même correspondance. Bouton « Échelle... » (`ScalePanel`, avec OK / Annuler, éditeur de courbe = `VelocityPanel` sans les réglages de fondu). **À valider dans Reaper.** Modulation : le bloc est maintenant découpé en morceaux de 64 échantillons (~1,3 ms) tant qu'une matrice existe (mesuré : environ 13 % de CPU en plus sur un banc de 32 voix, soit moins de 1 % d'un cœur) ; il n'y a toujours pas d'interpolation à l'intérieur d'un morceau.
- **Correctif FM (2026-10-25)** : `Exp2::lookup` (msfa) décale de `6 - (x >> 24)` ; avec un décalage de niveau d'opérateur très négatif (potard « FM Op N Level » à -99 sur les six opérateurs, ou modulation) le décalage sortait de 0..31 (comportement indéfini, gain énorme : crête 3,2). `third_party/msfa/dx7note.cc` borne maintenant le niveau entre 0 et 16 doublements. Test `tests/test_fm.cpp` (« extreme operator level offsets »).
- **Onglet MOD (2026-10-25)** : légendes des colonnes des LFO (forme, vitesse en Hz, phase en %) et des routes (source, n°, canal, quantité, plage, destination) ; la case « +/- » devient un bouton à deux états « 0..1 / -1..+1 » (la plage de la source ; grisé et fixé à -1..+1 pour un LFO ou le pitch bend ; l'inversion se fait par une quantité négative). Étiquette « ENV n » en haut à droite de l'éditeur d'enveloppe.
- **Constat (à valider)** : moduler `Track N Filter n Env Attack` ne bouge rien à l'écran (la page Filtres du synthé dessine l'enveloppe de la description, pas le décalage de modulation) et l'effet n'est pris qu'au Note On suivant (`SynthVoices::Params::EnvParams`).
