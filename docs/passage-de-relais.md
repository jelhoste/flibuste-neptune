## Architecture du dépôt

```
core/            moteur C++ portable, SANS JUCE (Engine, Parameter, ProbePool, State, Settings, Autosave, FileUtil, Undo, Theme, I18n, Profile, KnobInteraction, UiState, SampleLoader, Instrument, SamplerVoices, SamplerParams, Envelope, EnvelopeLayout, ZoneImport)

design/          maquette HTML (neptune_ui.html) + briques de style NOVA copiées telles quelles
docs/            brief, roadmap, spec, ce fichier

```

Règle d'architecture : le cœur n'inclut jamais JUCE. L'adaptateur ne contient aucune logique métier.

Options CMake : `NEPTUNE_BUILD_PLUGIN` (ON), `NEPTUNE_BUILD_TESTS` (ON), `NEPTUNE_PROBE_TRACKS` (32), `NEPTUNE_WITH_LIBSNDFILE` (ON : libsndfile 1.2.2 + dr_flac, lecture des samples), `NEPTUNE_WITH_EBUR128` (OFF : libebur128 v1.2.6, pas encore utilisé).

## Build, tests, CI

- **Environnement de développement** : Linux Mint. `cmake` n'est **pas installé** et les bibliothèques de développement de JUCE (apt) non plus : le plugin complet ne se compile donc **que par la CI** ; les tests du cœur se compilent localement avec un `cmake` en environnement virtuel :

  ```bash
  python3 -m venv /chemin/venv && /chemin/venv/bin/pip install cmake ninja
  export PATH=/chemin/venv/bin:$PATH
  cmake -S . -B build -G Ninja -DNEPTUNE_BUILD_PLUGIN=OFF
  cmake --build build && ctest --test-dir build --output-on-failure
  ```

- **Pour compiler le plugin en local** : installer les paquets listés dans `.github/workflows/build.yml` (étape « Dépendances système »), puis `cmake --build build --target Neptune_CLAP`.
- **CI** : à chaque push, build + tests du cœur + `.clap` archivé (`Neptune-Windows.zip`, `Neptune-Linux.tar.gz`, `Neptune-macOS.tar.gz`). Durée : 4 à 6 minutes. Le job de **Release** sur tag `v*` n'a **jamais été exécuté**.
- **Récupérer un binaire** : `gh run download <id> -R jelhoste/flibuste-neptune -n Neptune-Linux`. Chrome bloque parfois les archives contenant un `.clap` non signé : envoyer le `.clap` brut, ou le copier dans `~/.clap/` (Reaper sous Linux le lit déjà) puis *Re-scan*.
- **Tests utilisateur** : Windows et Linux validés sur chaque jalon ; **macOS jamais testé** (il compile en CI).

## Pièges déjà rencontrés (à ne pas refaire)

1. **clap-juce-extensions n'a pas de vraies versions** : le tag `0.26.0` pointe vers un commit de 2022. On fige un commit de `main` (`7adee3a`, CI amont verte avec JUCE 8.0.11). JUCE est figé à `8.0.11` ; JUCE 9.0.x existe, la CI amont le teste aussi, non adopté par prudence.
2. **Noms de tests Catch2 en ASCII uniquement** : `ctest` les passe en ligne de commande et Windows casse les accents.
3. **Identifiants de paramètres** : le `clap_id` est le hachage du texte de l'ID de paramètre JUCE (wrapper). On utilise `std::to_string(ParamId)`. Les ids du cœur sont **stables** : ne jamais les renuméroter (automation des projets). Schéma de la sonde : maître 1–4 ; piste *t* à `1000 + 100·t` (+0 volume, +1 pan, +2 mute, +3 solo, +4 type, +10…17 bypass d'inserts, +20…27 niveaux d'envois).
4. **Paramètres discrets** : seul `isBoolean()` est marqué « stepped » côté CLAP ; les sélecteurs à N valeurs sont vus comme un paramètre normalisé 0–1 avec texte. Cela fonctionne dans Reaper (validé).
5. **Cœur lié dans le `.clap`** : `neptune_core` doit rester en `POSITION_INDEPENDENT_CODE ON`, sinon l'édition de liens Linux échoue (révélé par nlohmann/json).
6. **Aperçu de la maquette** : le volet d'aperçu de l'application charge un fichier HTML en `data:` sans ses scripts voisins ; servir `design/` en HTTP (`python3 -m http.server --directory design`).
7. **Taille de l'éditeur JUCE en dernier dans le constructeur** : `resized()` place les composants, il doit les trouver. Fixer la taille avant de les créer ne place rien tant que l'hôte ne redimensionne pas la fenêtre (Reaper sous Linux ne le fait pas : potards absents à l'ouverture, apparus au premier redimensionnement ; Windows masquait le défaut). Constaté le 2026-10-12.
8. **Contrôle de syntaxe de l'adaptateur sans compiler le plugin** : cloner JUCE 8.0.11 en partiel (`git clone --depth 1 --filter=blob:none --sparse`, `sparse-checkout set modules`) et clap-juce-extensions au commit figé avec ses sous-modules `clap-libs/clap` et `clap-libs/clap-helpers`, puis `g++ -std=c++17 -fsyntax-only -DJUCE_GLOBAL_MODULE_SETTINGS_INCLUDED=1 -DJUCE_STANDALONE_APPLICATION=0 -I<juce>/modules -I<cje>/include -I<cje>/clap-libs/clap/include -I<cje>/clap-libs/clap-helpers/include -Icore/include -Iadapter-juce/src -I<json>/include` sur chaque `.cpp` de `adapter-juce/src`. Attrape les erreurs de compilation avant la CI (ne vérifie ni l'édition de liens ni l'affichage).
9. **Installer un `.clap` sans passer par Chrome** : `gh run download <id> -n Neptune-Linux`, décompresser, copier dans `~/.clap/` (garder l'ancien hors de ce dossier : Reaper scanne tout ce qui s'y trouve), puis fermer les instances et faire Re-scan.

## Décision : sorties audio

**Jeu fixe de 32 sorties stéréo = 64 canaux** (décision du 2026-10-15 ; c'était 64 sorties stéréo = 128 canaux, le plafond du wrapper, depuis le 2026-10-11). Une sortie directe ou la sortie du Master pointant sur 33..64 (anciens états) est ramenée à 32 par le clamp d'`sanitisedStrip`. Raison : 16 pistes + 16 bus = 32 sources possibles, les pistes parallèles passent par leur parent ; listes plus courtes, moins de tampons remis à zéro. Anciennement : (décision de l'utilisateur, 2026-10-11) : les *templates choisis à l'insertion* de la roadmap ne sont pas supportés par clap-juce-extensions. Reaper n'active que les 2 premières sorties et laisse l'utilisateur activer les autres, ce qui suffit. Pas de second plugin « Stereo/Multi ».

## Constats du point 4 (lecture du code de clap-juce-extensions + validateur)

Établis par lecture du wrapper au commit figé et par `clap-validator` ; **le comportement réel de Reaper reste à constater avec la fenêtre de sonde**.

- **Sorties** : un port CLAP par bus JUCE, stéréo ou mono seulement. Le wrapper plafonne à **128 canaux de sortie** (Neptune en déclare 64 depuis le 2026-10-15). Les *templates de sorties choisis à l'insertion* ne sont **pas** supportés par le wrapper (`audio-ports-config` : 0 configuration ; le validateur le signale « non implémenté »). Les ports sont fixes ; décision à prendre (voir questions ouvertes).
- **Latence** : `setLatencySamples()` → le wrapper demande un **redémarrage** à l'hôte (`request_restart`, puis `latency_changed` à la réactivation). Utilisable pour les modes de l'IR loader, pas pour de l'automation.
- **Transport/tempo** : transmis via `AudioPlayHead` (tempo, mesure, position en temps, lecture/boucle) ; le wrapper coupe le bloc aux événements de transport.
- **Notes CLAP** : avec `supportsNoteDialectClap`, l'hôte peut envoyer des notes avec `note_id`. Le chemin standard du wrapper les convertit en MIDI JUCE et **perd le `note_id`** ; la sonde les prend donc en `handleDirectEvent`. `supportsNoteExpressions()` du wrapper n'est **pas utilisé** : les expressions passent obligatoirement par `supportsDirectEvent` + `handleDirectEvent`.
- **Modulation** : `clap_juce_parameter_capabilities` sur le paramètre (mono + polyphonique) ; la modulation polyphonique exige que le plugin émette `NOTE_END` (fait par la sonde).
- **Résolution des événements** : `CLAP_PROCESS_EVENTS_RESOLUTION_SAMPLES` vaut 0 par défaut : l'automation n'est **pas à l'échantillon près** (appliquée au début du bloc). À revoir avant le palier 1 si la précision compte.
- **État** : après un chargement, le plugin doit demander `params.rescan(VALUES)` à l'hôte (fait via `updateHostDisplay`). `setStateInformation` étant `void`, le wrapper répond « succès » même pour un état refusé (avertissement du validateur, sans conséquence).
- **Validateur** : `clap-validator` s'exécute en CI Linux (binaire épinglé 0.4.1) ; le zip contient une `.tar.gz` imbriquée.

### Constats de la sonde dans Reaper (Linux, 2026-10-11)

- Validé : 64 sorties stéréo (le routage affiche « 2/128 out »), latence modifiable à l'exécution (compteur et compensation), transport/tempo/signature.
- Notes jouées : arrivent en **événements CLAP** (compteurs « CLAP note-ons » et « NOTE_END » identiques ; « MIDI note-ons » reste à 0, normal : les notes ne passent pas par la voie MIDI de JUCE).
- **Reaper ne fournit pas de `note_id`** (valeur -1) pour les notes jouées ; l'adressage d'une note se fait donc par canal + touche, pas par identifiant.
- **Non déclenchés** : expressions de note et modulation de paramètres (mono/poly). Non testé : MPE, aftertouch polyphonique, modulation LFO/ACS de Reaper. Ne pas supposer que Reaper les émet ; à reconstater si le besoin apparaît (hôte susceptible de les émettre : Bitwig).

## Réglages et autosave (point 5)

- **Dossier de configuration** : `~/.config/Neptune` (Linux), `%APPDATA%\Neptune` (Windows), `~/Library/Application Support/Neptune` (macOS). Contient `settings.json` (créé avec les valeurs par défaut au premier lancement) et `autosave/`.
- **Réglages** (`Settings.h`) : langue (`en`), thème (`dark`, défauts de la maquette), contraste 0–4 (0), profil de performance (`live`), 4 dossiers par défaut (vides), `autosave_interval_seconds` (60 ; 0 = désactivé ; minimum 5), `autosave_keep_days` (30). Lecture tolérante champ par champ (jamais bloquante). Valeurs par défaut du profil (`live`), de l'intervalle (60 s) et de la durée de conservation (30 j) : confirmées par l'utilisateur. Pas encore de menu pour les modifier : on édite le fichier ; le réglage est lu une fois au démarrage de l'instance.
- **Autosave** (`Autosave.h`) : chaque instance a un identifiant de 32 hexadécimaux inscrit dans l'état du projet (`instance_id`). Elle écrit `autosave/<id>.neptuneautosave` (seulement si l'état a changé depuis le chargement ou la dernière écriture) et le supprime à la fermeture propre. Un fichier dont le processus propriétaire (pid) n'existe plus est la trace d'un crash.
- **Récupération** : à la relecture du projet, l'instance reprend son identifiant et retrouve son autosave ; s'il diffère de l'état chargé, il est conservé (`.neptunerecovered`) et proposé par une bannière Restore/Discard dans la fenêtre de sonde, jusqu'à ce que l'utilisateur tranche. L'autosave peut être plus ancien que la dernière sauvegarde du projet : la bannière affiche sa date.
- **Limites connues** : un pid réutilisé par un autre processus après un redémarrage ferait passer un vieux fichier pour « vivant » (il n'est alors ni proposé ni purgé). Deux pistes dupliquées portent le même identifiant : la seconde garde un identifiant neuf (sans récupération jusqu'à la prochaine sauvegarde du projet, qui l'enregistre). L'identifiant venant d'un état de projet, il est validé (32 hexadécimaux) avant de servir de nom de fichier.

## i18n et thèmes (squelettes, palier 0)

- **i18n** (`I18n.h`) : `Translator(code)` ; anglais par défaut, français disponible. Tables **compilées dans le plugin** (pas de fichiers à installer). Chaque texte visible a une **clé** (`recovery.restore`) ; clé absente dans la langue → anglais, clé inconnue → la clé elle-même (visible). Textes à trous `{0}`, `{1}`. Le nom « Neptune » n'a pas de clé. Un test vérifie : pas de doublon, anglais obligatoire, mêmes trous dans toutes les traductions. Ajouter une langue : une colonne dans `I18n.cpp` + `languages()`. `settings.json` accepte n'importe quel code de langue ≤ 16 caractères ; un code non supporté retombe sur l'anglais.
- **Thèmes** (`Theme.h`) : les 4 thèmes avec leurs **jetons de couleur copiés de la maquette** (mêmes noms, `tokenCssName()`), style de potard (led/pot), style de contrôles (glass/bezel/hc), rayons, épaisseur de bordure. `withContrast(def, niveau)` est le **port exact de `design/nova-contrast.js`** ; vérifié en exécutant le JS réel dans le volet navigateur : 163 valeurs sur 163 identiques (3 thèmes × niveaux 1–4). Le thème haut contraste n'est jamais modifié.
- **Pas repris** : les ombres (`--csh`, `--fsh`, `--ctl-sh`) et les dimensions des composants des contrôles (`nova-controls.css`) ; à décider quand les composants de l'interface seront écrits.
- **Branché** : seulement la fenêtre de sonde (couleurs depuis le thème/contraste de `settings.json`, textes de la bannière de récupération et de la latence via les clés). Pas de menu : on édite `settings.json`, lu une fois au démarrage. Partie adaptateur compilée par la CI (verte) et **validée dans Reaper par l'utilisateur** (langue, thème, contraste).

## AnalogSynth (plugin séparé) et système de presets (2026-10-15, à valider dans Reaper)

**Ce qui est livré** (cœur testé : 29 tests ajoutés, 321 au total ; adaptateur contrôlé à la syntaxe contre JUCE 8.0.11, jamais compilé ni écouté : à valider par la CI puis dans Reaper) :

- **Plugin CLAP « AnalogSynth »** (nom provisoire, `com.tournedosrossini.analogsynth`, cible CMake `AnalogSynth`, archivé par la CI sous `AnalogSynth-<OS>`, validé par `clap-validator`). Le synthé soustractif de Neptune (même moteur `Synth.h` / `SynthVoices.h`, même vue `SynthView`) sans mixeur : un volume et un pan propres, gain, accordage, 2 filtres, 15 paramètres du synthé automatisables (mêmes identifiants que la piste 0 de Neptune), limite de voix comme dans Neptune (16 par défaut, plafond 64, décision de ne pas l'étendre : 64 voix en unisson 8 coûtent déjà ~38 % du budget). Notes MIDI appliquées à leur position dans le bloc ; clavier à l'écran (file sans verrou vers l'audio) ; annuler/rétablir ; état JSON `analogsynth-state`.
- **Cœur** : `AnalogSynth.h/.cpp` (paramètres, moteur `AnalogSynthEngine`, état, capture / application de preset, presets d'usine), `Preset.h/.cpp` (modèle de données), `PresetLibrary.h/.cpp` (disque). `Mixer.h` : `addSynthParams` partagé avec Neptune.
- **Modèle de données** : le document de l'utilisateur est copié dans `docs/modele-donnees-presets.md` (référence ; incohérence relevée : `.tbank` dans le titre du §7, `.flibank` partout ailleurs, `.flibank` retenu) ; extension `.flipreset` (un preset), `banks.json`, `config.json`, grilles `grids/<id>.json`, corbeille `trash/AAAA-MM-JJ_HHhMM_<nom>/` (+ `meta.json`), bundle `.flibank` (zip fait par JUCE : `bundle-manifest.json` + `presets/<id>.flipreset`) ; `schemaVersion` partout, clé inconnue ignorée, version supérieure acceptée ; recherche à facettes (OR dans une clé, AND entre clés ; caractéristiques en OR) ; stepper (le passage à la banque suivante dépend de `wrapToNextBank`, sinon on reboucle dans la banque ; les emplacements vides sont sautés) ; MIDI Bank Select (CC 0 = index de banque 0..127) + Program Change ; emplacement vide : **le preset actuel reste**, rien n'est demandé.
- **Extension du modèle** (décision de conception, à valider) : le fichier preset porte en plus `module` ("analogsynth") et `state` (la description structurée du synthé : formes, enveloppes, filtres, unisson), car `parameters` seul est à plat. `parameters` contient les paramètres automatisables capturés (clés « osc1.level », « filter1.cutoff »... table `keyedParams()`). Défauts de capture d'AnalogSynth : **libres** `output.volume`, `output.pan`, `synth.glide` ; tout le reste capturé ; exception par preset (`parameterCaptureOverrides`) respectée à l'enregistrement et à l'application.
- **Limite connue** : la **capture par voix** (les notes en cours gardent l'ancien son quand on change de preset) n'est **pas** implémentée (décision : plus tard). Au changement de preset, toutes les voix prennent le nouveau patch immédiatement ; le fichier stocke déjà capturé / libre, rien à migrer. De même `pedalHeldBehavior*` et le pool de réverbes (`reverbPool`) sont lus et écrits mais sans effet (pas de pédale de sustain ni de réverbe dans ce plugin). Pas de molette de pitch bend dans le synthé (pas d'API dans `SynthVoices`).
- **Interface** : barre de preset en haut (précédent, nom avec `*` si modifié et verrou, suivant, Enregistrer, « Presets... »), gestionnaire superposé à 5 onglets (Presets : recherche, détails, enregistrement, corbeille, affectation banque / tuile ; Banques : 0..127 x 128 programmes, nom, export / import `.flibank`, import `.flipreset` ; Grille concert : 8x8 tuiles, verrou à appui long, poignée de glisser-déposer, intégrité signalée par un badge et réparable ; Corbeille ; Réglages : capturé / libre, rétention). « Enregistrer » sur un preset factory ou verrouillé ouvre « Enregistrer sous » (champ du nom). Le dossier des presets vient de `presetsDir` dans `settings.json`, sinon `<config>/Neptune/AnalogSynth/`.
- **Piège** : un preset factory n'est pas sur disque (`factoryPresets()` en code, ids stables `factory-analogsynth-NN` : les banques les référencent, ne pas les renuméroter). `Library::importPreset` ne garde l'id que s'il est libre. Les ids lus d'un fichier ou d'un bundle sont validés (`[A-Za-z0-9_-]`, 64 max) avant de servir de nom de fichier.
- **Points à confirmer dans Reaper** : 1) le Program Change / Bank Select arrivent bien à `processBlock` (le wrapper CLAP convertit les `CLAP_EVENT_MIDI` en MIDI JUCE ; non vérifié pour les CC et les Program Change) ; 2) la fenêtre de sélection de fichier (export / import) s'ouvre bien depuis l'hôte (Linux : GTK / Zenity selon JUCE) ; 3) l'automation enregistrée quand on charge un preset (les paramètres modifiés sont signalés à l'hôte avec un geste) ; 4) mise en page : jamais vue à l'écran.

## Palier 1 — Synthé soustractif, premier jet + pistes actives (2026-10-13, à valider dans Reaper)

- **Pourquoi** : tester le mixeur avec des sons faciles à reconnaître (une note tenue, un niveau constant) plutôt qu'avec des samples. Décisions de l'utilisateur : périmètre minimal (1 oscillateur + enveloppe de volume + 1 filtre avec son enveloppe) ; le sélecteur de type est **en haut de la bande du mixeur** (comme la maquette `design/neptune_ui.html` : pastille SMP / SYN) ; l'édition se fait dans une **vue séparée** ; **un projet neuf n'a qu'une piste, réglée sur Synthé** ; pistes à ajouter par un bouton « + » ; au chargement d'un ancien projet, seules les pistes utilisées sont affichées ; changer le type de piste efface sa configuration d'instrument (spec §1) après confirmation.
- **Cœur** : `Synth.h` (`TrackType` Sampler/Synth, `Waveform` sinus/triangle/dent de scie/carré, `SynthDescription` : forme d'onde, octave ±3, enveloppe de volume AHDSHR, **un filtre** `FilterSettings` réutilisé tel quel (SVF/Échelle, mode, pente, suivi du clavier, vélocité, profondeur d'enveloppe, drive, son enveloppe), polyphonie poly/mono/legato, limite 1..64 (16 par défaut), vol de voix, glissando ; `SynthPatch` = la description + les tables d'enveloppes, immuable, remise au thread audio). `SynthVoices.h` : oscillateurs **à bande limitée** (PolyBLEP pour la dent de scie et le carré, PolyBLAMP pour le triangle ; mesuré : 23 à 34 fois moins de repliement que la forme naïve), marge par voix à pleine vélocité (`kVoiceHeadroom` 0,15 depuis le 2026-10-14 : sinus -16,5 dBFS, dent de scie ~-15 dBFS ; c'était 0,3, jugé trop fort), contrôle (hauteur, filtre) toutes les 16 échantillons. **Mêmes paramètres automatisables que le Sampler** : gain, accordage (demi-tons, cents), coupure et résonance du filtre 1 (`mixer::samplerParam`) : les potards du bas sont donc les mêmes quel que soit le type (le second filtre n'est pas affiché pour un synthé). `HandoffSlot<T>` (modèle générique) remplace le code de `InstrumentSlot` (alias conservé). `DescriptionJson.h` expose les briques JSON enveloppe / filtre.
- **Moteur** : par piste `type` et `active` (atomiques), `synthSlot`, `SynthVoices`. `Engine::setTrackType`, `publishSynth`, `setTrackActive`. Un changement de type ou la désactivation d'une piste **coupe net ses voix**. Une piste inactive ne reçoit pas de note et ne produit rien (le moteur garde ses 16 emplacements : pool fixe). Les voix du synthé figurent dans le moniteur de voix (sans zone). Mesure (outil de performance, 256 échantillons) : 16 voix ~2 % du budget, 64 voix avec SVF 24 dB ~8 %, avec enveloppe de filtre ~14 %.
- **État, schéma v6** : par piste `active`, `type` (si Synthé), `synth` (si différent du défaut) ; `MixerState::freshProject()` (une piste Synthé), `resetTrack`, `fixSelection` (la sélection est toujours une piste active). Migration v5 -> v6 : sans transformation ; `active` absent = **déduit** (piste 1, ou piste avec instrument, nom, routage... : active ; les autres : masquées). Les pistes masquées d'un ancien projet gardent leurs valeurs de paramètres (fader...) : elles sont remises à zéro quand on rajoute une piste.
- **Processeur** : `trackType`, `trackActive`, `activeTrackCount`, `trackHasContent`, `synthDescription`, `uiEditSynth` (annulable, fusionné par geste), `uiSetTrackType` (efface l'instrument et le patch, remet à zéro gain/accordage/filtres, **vide l'historique d'annulation**), `uiAddTrack` (première piste libre, **réglée sur Synthé**, sélectionnée), `uiRemoveTrack` (impossible s'il n'en reste qu'une ; **vide l'historique d'annulation**), `uiNoteOnTrack` / `uiNoteOffTrack` (une touche tenue s'arrête sur la piste où elle a démarré).
- **Interface** : en haut de chaque bande de piste, la pastille de type (menu : Sampler, Synthé ; FM et Entrée audio grisés « plus tard ») et le retrait de la piste (×) ; bouton « + Piste » après la dernière piste ; hauteur des bandes 292 px. Vue **Synthé** (à la place de la vue Mapping quand la piste sélectionnée est un synthé) : forme d'onde, octave, polyphonie, enveloppe de volume (le même éditeur graphique), filtre et son enveloppe, **clavier à l'écran** (3 octaves, souris et tactile multi-doigts, boutons Oct -/+, **Maintien** ou Maj+clic pour laisser une note sonner). La liste déroulante de piste n'affiche que les pistes actives.
- **Non fait** : 3 oscillateurs + sous-oscillateur + bruit, unisson, second filtre, enveloppe de pitch, explorateur de formes d'onde par catégories, ondes « analogiques » nommées (spec §2) ; vélocité du clavier à l'écran fixe (0,8) ; pas de présélection de sons ; annulation de l'ajout / du retrait / du changement de type de piste.
- **Points à confirmer par l'utilisateur** : une piste ajoutée avec « + » est un **Synthé** (la spec ne dit rien) ; marge de niveau d'une voix (-10,5 dBFS) ; la dent de scie comme forme par défaut ; la relecture à la réouverture d'un ancien projet (seules les pistes utilisées sont montrées).

## Palier 1 — jalon 3 : zones multiples et import par nom de fichier (écrit, à valider dans Reaper)

- **Décisions de l'utilisateur (2026-10-12)** : le gabarit de nom se définit **à partir d'un exemple** (caractères sélectionnés ; segments par délimiteur OU position « 2 à 3 caractères à partir du 8e », depuis le début ou la fin) ; **numéros MIDI préférés**, noms de note (C3...) acceptés avec **la correspondance d'octave affichée et réglable** (do central = C3 / C4 / C5 ; défaut C4 = 60, ce que confirme `048_C3v11`) ; vélocité : valeur, borne basse, borne haute, numéro de couche, nombre de couches ; **étendues : « aucune extension » par défaut**, avec « à mi-chemin » et « étendue fixe » en option, pour les notes comme pour les vélocités ; fusion des couches de vélocité **au niveau de l'instrument** (pas encore faite) ; **streaming disque obligatoire pour les gros instruments (jalon 4, juste après)**.
- **Cœur** (`ZoneImport.h`, ~25 tests) : `Template` (délimiteur + règles : rôle, segment, début, longueur min/max, convention d'octave ; JSON), `parseName`, `planImport` (étendues, couches, round-robin, doublons, contrôles de cohérence), `Plan` avec diagnostics. **Rôles** : ignorer, note (numéro / nom), note basse/haute, demi-tons sous/au-dessus de la racine, vélocité (valeur / basse / haute / numéro de couche / nombre de couches), nuance (ppp à fff, ordonnée → couche), round-robin (numéro ou lettre), groupe (micro, articulation...), marqueur de relâchement.
- **Expressions (ajout du 2026-10-12, à la demande de l'utilisateur)** : les mêmes caractères peuvent dire des choses différentes selon le fichier (`RR3` = round-robin 3, `SUS` = au Note On, `REL` = au relâchement). Une **règle par expression** cherche un mot (insensible à la casse) : n'importe où dans le nom, à une position précise (début du mot), ou dans un segment ; elle peut donner un **déclenchement** (inchangé / Note On « sustain » / relâchement), un **Groupe**, et un **rôle aux N chiffres qui suivent le mot** (round-robin, note, vélocité, couche...). Les règles par expression s'appliquent après les champs positionnels, dans l'ordre ; si le mot est absent la règle ne dit rien (donc pas d'erreur) ; mot trouvé sans les chiffres attendus → erreur signalée. Dans l'assistant : section « Expressions », menu « Expression à partir de ce texte » sur une sélection de caractères, et **cliquer une ligne de l'aperçu montre ce nom dans l'exemple** (pour définir les expressions à partir de plusieurs fichiers).
- **Échantillon principal et instrument léger (2026-10-12)** : un fichier SANS numéro de round-robin à une place qui en a (ex. `SUS` à côté de `RR1`, `RR2`) est **l'échantillon principal** (numéro 0) ; il joue en alternance avec les autres (numéro 0 en premier) ; deux principaux à la même place = doublon. **Chargement sélectif en cours d'utilisation** (vue Sampler, panneau « Tables chargées ») : la description garde toutes les zones ; on peut ne charger que le principal de chaque place, ne pas charger les échantillons de relâchement, ou laisser sur le disque un Groupe entier (pédale, articulation...) ; réversible (recharge depuis le disque) ; la mémoire est vraiment libérée (le cache n'est conservé que pour ce qui est chargé). Sauvegardé avec le projet.
- **Éditeur d'enveloppe en une seule courbe (2026-10-12, demande de l'utilisateur)** : plus de colonnes fixes. `EnvelopeLayout.h` (cœur, 8 tests) : la largeur d'un segment reflète sa durée (échelle logarithmique, ln(1 + t/8 ms)), **0 ms ou désactivé = largeur nulle** (le segment suivant démarre tout de suite), largeur minimale de 8 px pour un segment actif non nul, tout tient dans la largeur disponible, une enveloppe courte n'est pas étirée. **Échelle figée pendant un glissé** : ce qui précède le segment touché ne bouge pas, seule sa fin suit le pointeur, ce qui suit se décale ; recalcul au relâchement. Les **durées s'écrivent sous les boutons d'activation** (Dly, Atk, Hold, Dec, Rel), toujours alignées et jamais superposées (retour de l'utilisateur : les étiquettes sous la courbe s'empilaient) ; une valeur se **glisse** (faire varier, même depuis 0 ms) ou se **touche** (saisie en chiffres) ; le segment correspondant s'illumine sur la courbe. Sur la courbe on peut tout régler directement : nœud de fin de segment (durée), **nœud du délai à 0 ms collé à la marge gauche** (à tirer vers la droite), **poignée du plateau** (niveau de sustain ; le descendre active le decay, un decay à 0 ms étant un saut direct), poignée de forme au milieu des courbes. **Chaque segment activé a toujours sa poignée, même à 0 ms** (retour de l'utilisateur) : délai collé à la marge gauche sur la ligne de base, attaque au sommet, decay sur la chute au niveau de sustain, relâchement au bout du plateau, et pour le **hold à 0 ms** une poignée creuse sur un prolongement pointillé du niveau haut. Les poignées sont dessinées hors du rognage de la courbe (aucune n'est coupée par le bord). Les cartes de durée portent un **petit signe du mode de courbe** (`dB`, `lin`, `cvx`, `ccv`) pour attaque, decay et relâchement.
- **Tous les segments actifs par défaut (2026-10-12, demande de l'utilisateur)** : une nouvelle zone (import, « Load sample... ») démarre avec délai, attaque, hold, decay et relâchement activés, pour que **toutes les poignées de la courbe soient utilisables dès le chargement**. Sans effet audible : durées à 0 ms et sustain à 1 = enveloppe neutre, seul le relâchement (50 ms) agit. Le réglage prédéfini « Tenu (tous les segments) » est ce réglage de départ ; les réglages « percussion » désactivent explicitement les segments inutiles. **Les instruments déjà enregistrés gardent leurs interrupteurs** (activer tout changerait le son d'un decay désactivé avec un sustain < 1) : choisir « Tenu (tous les segments) » dans le menu les active.
- **Chargement sélectif** (vue Sampler, panneau « Chargé en mémoire », 2026-10-12) : cases pour les alternatives round-robin, les échantillons de relâchement et chaque Groupe nommé (articulation, pédale, micro...), avec la taille indicative (taille des fichiers). Décocher laisse sur le disque (la description garde tout, sauvegardée avec le projet) et **libère la mémoire** ; recocher recharge depuis le disque. `loadedZones()` (cœur) décide ce qui est chargé ; les notes en cours sur une zone déchargée s'arrêtent.
- **Jamais de choix silencieux** : nom illisible ou note absente → erreur, fichier exclu ; deux fichiers à la même place → erreur (sauf si le gabarit a un champ round-robin) ; numéro et nom de note qui se contredisent → avertissement, le numéro l'emporte ; valeur hors bornes → erreur ; couches manquantes sur certaines notes → information ; chevauchement d'étendues → avertissement. - **Mémoire exacte à l'import (2026-10-12)** : `core/MemoryBudget.h` + `probeAudioFile` (`SampleLoader.h`). L'en-tête de chaque fichier donne frames × canaux × (2 octets si 16 bits, 4 sinon) : mêmes règles de conservation que le chargement (testé : la prédiction égale `SampleData::bytes()` en WAV 16/24/32/float, mono/stéréo, FLAC 16/24). - **Groupes de choke et conditions de déclenchement (2026-10-13, jalon 7, premier jet)** : par zone, deux champs indépendants `chokeCuts` (le groupe que le déclenchement de la zone coupe) et `chokeCutBy` (le groupe qui peut la couper), numéros 1 à 32 (0 = aucun) ; **réglage simple dans la barre de la vue Mapping : un seul numéro = les deux champs identiques (groupe symétrique)**, bouton « ... » pour le réglage avancé (fenêtre `ChokePanel`) ; la liste affiche « Avancé » quand les deux diffèrent. Les zones de relâchement peuvent aussi choker. **Condition de déclenchement** par zone d'attaque (`trigger`) : Attaque (toujours), **Premier** (seulement si aucune autre note du Groupe n'est tenue), **Legato** (seulement si une autre note du Groupe est tenue) ; le menu « Déclenchement » règle aussi Relâchement (`onRelease`). Le « Groupe » est celui de la zone (vide = les zones sans Groupe) ; une note « tenue » = **touche encore enfoncée qui a déclenché une zone de ce Groupe** (suivie indépendamment des voix : elle compte même si son échantillon est fini ou si le mode mono a coupé sa voix). **Ne pas confondre** avec le legato de la polyphonie : celui-ci (mode d'instrument « Mono legato ») change la hauteur de la voix en cours, sans choisir de nouvelle zone ; le « Legato (transition) » de zone joue un échantillon de transition quand une autre note est tenue, et ne se déclenche donc jamais en « Mono legato » (utiliser Polyphonique ou Mono retrigger). **Priorité (indépendante de l'ordre de déclaration)** : parmi les zones qui couvrent la note, d'abord celles dont la condition « Legato » est satisfaite, sinon celles dont la condition « Premier » l'est, sinon les zones normales ; dans une catégorie, la première gagne. Les couches de conditions différentes ne forment jamais la même place (pas d'alternance round-robin entre elles) ni de fondu. Repères dans la matrice : « C3 » / « C3>5 » (choke), « P » (Premier), « L » (Legato).

- **Polyphonie (2026-10-13, jalon 6, premier jet)** : bouton « Polyphonie... » de la matrice → fenêtre flottante (`PolyphonyPanel`, annulable, Ctrl+Z, mise à jour si on annule pendant qu'elle est ouverte). - **Réponse de vélocité et fondu entre couches (2026-10-12, jalon 5)** : bouton « Vélocité... » de la matrice → fenêtre flottante (`VelocityPanel`). **Courbe de l'instrument** (`core/VelocityResponse.h`) : `shape` ∈ [-1,1] (sortie = entrée^(2^(3·shape)) ; < 0 douce, > 0 dure) + préréglages (linéaire, douce, très douce, dure, très dure) **et/ou points** (max 16, espacés d'au moins 0,02, y croissants) : avec des points la courbe passe par eux en interpolation monotone de Fritsch-Carlson (jamais de dépassement ni de recul) et la forme est ignorée ; table de 128 entrées pour l'audio, **bypass exact quand la courbe est linéaire**. Appliquée AVANT le choix des couches et le volume (la vélocité des zones de relâchement est celle déjà remappée). **Fondu entre couches** : les zones d'une même *famille* (mêmes notes, même Groupe, même déclenchement) forment des couches ; **largeur automatique** par instrument (0 = commutation franche, jusqu'à 64 vélocités ; fondu centré sur la frontière entre couches jointives, demi-largeur bornée par la moitié de chaque couche voisine) **et** fondu sur les **chevauchements explicites** (partiels : sur toute la zone commune) ; **couches imbriquées ou de même étendue : elles jouent toutes à pleine puissance** (empilement, décision de l'utilisateur ; ce n'est plus « la première gagne » comme avant). Courbe du fondu : puissance constante (sin/cos) par défaut, linéaire en option. Round-robin : compteur indépendant par couche. Une note déclenche donc plusieurs voix (jusqu'à 16 zones) : le fondu double le nombre de voix aux frontières. La matrice dessine en bandes claires la partie des couches qui joue en fondu au-delà de leur plage. Réglages sauvegardés avec l'instrument (`velocity_fade_width`, `velocity_fade_linear`, `velocity_curve`) et annulables.

- **Matrice notes × vélocité (2026-10-12, jalon 5, premier jet)** : vue **Mapping** (décision de l'utilisateur, 2026-10-12 : **il n'y a plus que deux vues, Mapping et Probe** ; la vue Sampler est supprimée, tout y est regroupé) : en haut Load sample / Importer / mode / liste (afficher-masquer) / état, puis note racine / supprimer ; à gauche la liste des zones (rétractable) et le panneau « Chargé en mémoire » ; au centre la matrice puis l'enveloppe ; les potards (gain, accordage) en bas. Sélection partagée avec la liste. **Annulation par différences** (`core/InstrumentEdit.h`) : une entrée par geste, ne garde que les zones modifiées (copie complète seulement si le nombre de zones change). Zones de saisie des bords : 24 px de large ; un rectangle étroit garde son tiers central pour le déplacement (zoomer pour le saisir).
  - **Non fait** : couches de vélocité en fondu enchaîné, courbe de vélocité de l'instrument, aimantation/grille, création d'une zone par glisser-déposer d'un fichier sur la matrice (spec §Zone clavier), recherche/filtre dans la matrice, déplacement à la flèche du clavier.
- **Streaming disque (2026-10-12, jalon 4, premier jet)** : réglage **par instrument** (sauvegardé avec lui : `stream_from_disk`, `preload_kb`), accessible en cours d'usage dans le panneau « Chargé en mémoire » (case + préchargement 32 Ko à 4 Mo, **128 Ko par sample par défaut** : décision de l'utilisateur, remplace les « 200-500 ms réglables dans les réglages généraux » de la spec §22). Tout-RAM reste le défaut et reste disponible. Mécanique (`core/.../DiskStreamer.h`) : `SampleData` garde `frames` = longueur du fichier et `residentFrames` = ce qui est en mémoire ; un thread disque (`std::thread`, sondage 1 ms) remplit un tampon circulaire de 16 384 frames par voix (80 emplacements = 64 voix + 16 fondus, ~10,5 Mo alloués au premier instrument streamé) ; l'audio lit d'abord la partie résidente puis le tampon, ne fait jamais de disque ni d'allocation ; protocole sans verrou (compteur de demande impair/pair, `ready`, `writePos`/`readPos` atomiques, paramètres de demande en double exemplaire). **Zones en boucle** : tout ce qui précède la fin de boucle (+4) reste en mémoire, jamais de flux. **Sous-alimentation** : si le disque n'a pas livré à temps, la voix s'éteint en fondu court (3 ms) sur ce qui est disponible, l'incident est compté et affiché dans la ligne d'état (« streaming : N coupure(s) »). Estimation de mémoire et chargement partagent `residentFramesNeeded` (testé : l'estimation égale la mémoire réelle de l'instrument construit + tampons). Rendu streamé **identique bit à bit** au rendu tout-RAM (test). Limite de zones lues dans un état : relevée de 4 096 à 32 768 (un piano la dépassait).
  - **Validé par l'utilisateur (2026-10-12, Reaper)** : 60 notes tenues plusieurs secondes simultanément, répété de nombreuses fois, aucune coupure audible (disque et instrument non précisés).
  - **Non fait / à valider** : mesure sur disque réel (HDD, 64 voix) ; priorité du thread disque ; chemins > 1 024 octets (chargés en entier) ; tampon 16 384 frames pour des transpositions très hautes (au-delà de ~4× la vitesse, sous-alimentation possible) ; matrice et autres éléments de l'ordre « Ensuite ».

## Palier 1 — jalon 2 : enveloppe d'amplitude (validé)

- **Décisions de l'utilisateur (2026-10-12)** : **un seul Hold**, entre l'attaque et le decay (le second de la roadmap est abandonné) ; affichage **graphique** de la courbe où l'on déplace les temps ET les formes ; l'enveloppe **agit aussi en one-shot, Note Off ignoré** ; des **réglages prédéfinis pour percussions** (attaque seule, ou attaque + hold + decay), les segments étant activables/désactivables un par un.
- **Segments** : Délai (spec : retarde le début de l'attaque, pas le sample), Attaque, Hold, Decay, niveau de Sustain, Relâchement. Chacun a un interrupteur ; désactivé = sauté ; tout désactivé = enveloppe neutre (gain 1, pas silence). Temps 0 à 10 s (relâchement ≥ 1 ms). Défaut : tout neutre, relâchement actif 50 ms (comportement du jalon 1).
- **Formes** : linéaire ; paramétrique `shape` ∈ [−1, 1] (g(x) = x^(2^(−3·shape)), >0 convexe) ; **linéaire en dB** (plancher −60 dB, ramené à 0 exactement ; decay vers un sustain > 0 : dB exactement linéaire). Tables de 256 points précalculées par zone hors temps réel (`EnvelopeRuntime`) ; une valeur par échantillon (`EnvelopeRunner`), sans allocation.
- **Comportements voulus** : decay vers sustain 0 → la voix est libérée dès l'enveloppe à zéro (utile pour couper la queue d'un son) ; relâchement désactivé en mode boucle → fondu de secours de 2 ms (anti-clic) ; Note Off pendant l'attaque → relâchement depuis le niveau atteint, sans saut.
- **Édition en direct** : changer un réglage de zone republie l'instrument ; **les voix qui jouent continuent** (même indice de zone et même sample) avec les nouveaux réglages (enveloppe, hauteur, gain). Un autre sample arrête les voix.
- **Valeurs prédéfinies** (`EnvelopePreset`, à affiner à l'oreille) : Tenu = tout neutre ; Percussion attaque seule = attaque 3 ms forme 0,4, relâchement off ; Percussion attaque + hold + decay = attaque 2 ms, hold 20 ms, decay 300 ms forme 0,6 vers 0, relâchement off. Ce sont des configurations de la même enveloppe, pas un autre type : le futur gestionnaire de presets (palier 6) pourra les réutiliser.
- **Format** : schéma d'état **v4** ; `release_ms` des zones du jalon 1 est relu comme enveloppe (relâchement seul). Les chemins du v3 se rechargent.
- **Éditeur graphique** (`EnvelopeEditor`, adaptateur) : 5 colonnes (Délai, Attaque, Hold, Decay, Relâchement) + plateau de sustain ; glisser un nœud horizontalement = temps (échelle cubique : précision sur les temps courts), le nœud de fin du decay aussi verticalement = niveau de sustain ; la poignée au milieu d'une courbe, glissée verticalement = forme ; **double-clic sur la poignée = forme linéaire ; appui long ou clic droit = bascule dB** (poignée creuse) ; interrupteurs par segment et menu de réglages prédéfinis. Zones de saisie de 44 px (tactile).
- **Fenêtre** : deux vues, **Sampler** (chargement, mode, note racine, enveloppe, potards) et **Probe** (l'ancien diagnostic hôte) ; bouton en haut à droite. Le relâchement n'a plus de curseur dédié (il est dans l'enveloppe).
- **Limites** : l'enveloppe est par zone (l'héritage par Groupe de la spec viendra avec les Groupes) ; les modifications de zone ne passent pas par l'annulation (comme avant) ; pas de lecture de la forme au clavier ; l'affichage ne montre pas la durée réelle du sample ni le sustain en temps.
- **Validation (2026-10-12)** : testé par l'utilisateur sous Windows et Linux, souris et tactile : fonctionne.
- **Coût** : `neptune_perf_callback` (64 voix en boucle, enveloppe neutre) : environ **6,5 % du budget temps réel** (5 % au jalon 1) ; l'enveloppe ajoute ~1,5 point à cette charge, sans optimisation.

## Potard générique et modale (palier 0)

- **Gestes** (décision du 2026-10-12, spec mise à jour) : glisser vertical = valeur ; **Shift, ou clic droit maintenu et déplacé = réglage fin** ; **double-clic / double-tap = valeur par défaut** ; **appui long (clic gauche maintenu ou doigt) ou clic droit relâché sans bouger = modale** ; molette (Shift = pas fin) ; clavier : flèches, PageUp/PageDown, Début/Fin, Entrée = modale, Suppr = défaut. Au tactile le réglage fin passe par la modale. Ctrl/Cmd+Z annule, Ctrl/Cmd+Maj+Z ou Ctrl+Y rétablit.
- **Conséquence à ne pas oublier** : le clic droit ouvre maintenant la modale, pas un menu. Quand viendront « Apprendre » (MIDI Learn, palier 3) et « Ajouter à la Façade » (palier 2), leurs entrées devront vivre dans la modale (ou un menu à part) : à décider alors.
- **Cœur** (`KnobInteraction.h`, 14 tests) : machine à états pure (sans JUCE), pilotée par des événements horodatés. Tous les réglages sont dans `KnobConfig` : seule la sensibilité du glisser (0,006 par pixel) vient de la maquette ; **les autres valeurs sont des points de départ à affiner à l'usage** : réglage fin ×0,1, appui long 500 ms, tolérance de mouvement 3 px (souris) / 8 px (doigt), double-tap 400 ms et 6 / 24 px, pas de molette 0,02 (fin 0,002), pas de flèche 0,01 (fin 0,001, PageUp/Down 0,1 ; paramètres discrets : un pas / un dixième). **Zone tactile minimale : 44 px** (`minTouchTarget`, valeur proposée et confirmée, pas une norme vérifiée).
- **Adaptateur** : `NeptuneKnob` (dessin « led » et « pot » portés de `nova-knob-styles.js`, jetons du thème actif), `KnobModal` (champ texte avec saisie d'unités, slider, remise au défaut, redimensionnable, superposée à la fenêtre du plugin, pas de fenêtre système). Taille de la modale mémorisée **par type de terminal** (souris/tactile) dans `ui_state.json` (`UiState.h`), distinct de `settings.json`.
- **Undo branché** : chaque geste passe par `UndoManager` ET prévient l'hôte (début/fin de geste, `setValueNotifyingHost`). Annuler/rétablir ne sont **pas** des événements d'automation : l'hôte relit les valeurs (même mécanisme qu'au chargement d'un état) ; il n'enregistre donc pas l'annulation comme un geste d'automation.
- **Interface** : 4 potards de test dans la fenêtre de sonde (Master Volume, Master Pan, FM Algorithm, Track 1 Volume) + boutons Annuler/Rétablir. Hauteur de la fenêtre passée de 820 à 920.
- **Pas fait** : variante « fader vertical qui devient rotatif selon la hauteur » (c'est le mixeur, palier 1) ; potards bipolaires (le dessin les gère, rien ne les utilise) ; tailles de modale par instrument.
- **Vérification** : adaptateur contrôlé à la syntaxe contre les vrais en-têtes JUCE 8.0.11 (4 fichiers, sans erreur) ; la CI le compile en entier. Validé par l'utilisateur dans Reaper : Windows en tactile, Linux (après correction de la disposition, piège 7).

## Profils Live/Studio (mécanisme, palier 0)

- **Aucun traitement n'a encore de variante** : le mécanisme est en place, `Engine::profile()` est lu à chaque bloc, rien ne change à l'oreille. Les futurs traitements à latence (oversampling, look-ahead, convolution, time-stretch) liront `Engine::profile()`.
- **Réglage global par processus** (`Profile.h`, `SharedProfile::process()`) : toutes les instances du plugin chargées dans le même processus Reaper le partagent (variable statique du `.clap`, lecture sans verrou). La **première** instance l'initialise depuis `performance_profile` de `settings.json` ; les suivantes ne l'écrasent pas.
- **Décision (2026-10-11) : la bascule n'est jamais réécrite dans `settings.json`** ; elle vaut jusqu'à la fermeture du processus. `settings.json` ne change qu'à la main.
- **Verrou par instance** (`InstanceProfile`) : l'instance garde son profil même si le global bascule. **Décision : le verrou est sauvegardé dans le projet** (`"profile_lock": "live"|"studio"`, absent = non verrouillé). Une valeur illisible est lue comme « non verrouillé ».
- **Schéma d'état passé en v2** (le seul changement : ce champ facultatif). Migration v1→v2 enregistrée (aucune transformation : un document v1 est un v2 valide). Conséquence : **une version plus ancienne du plugin refuse les projets enregistrés par celle-ci** (« état trop récent », rien n'est chargé).
- **Interface** : la fenêtre de sonde a deux boutons (basculer le profil global, verrouiller/déverrouiller l'instance) et une ligne d'état. Pas de menu final.
- **Projet marqué modifié** : constaté dans Reaper (2026-10-12) que le changement de verrou ne marquait pas le projet ; corrigé en déclarant un changement d'état hors paramètres (`withNonParameterStateChanged`, que le wrapper traduit en `mark_dirty` de CLAP ; vérifié dans le code de clap-juce-extensions et de JUCE 8.0.11). La bascule du profil **global** ne marque rien : elle n'est pas dans le projet (décision). **Validé dans Reaper par l'utilisateur** (2026-10-12), ainsi que la bascule et le verrou à deux instances et la relecture du verrou après réouverture du projet.

## Format d'état JSON (point 3) : décisions et suite

- Chargement **tout ou rien** : document invalide ou plus récent → refus, aucun paramètre modifié. Plus ancien → migration silencieuse (`registeredMigrations()` : un saut n → n+1 par version ; un test garde-fou échoue si on monte `currentSchemaVersion` sans l'enregistrer).
- Toutes les valeurs sont sauvegardées (pas seulement celles ≠ défaut) : changer un défaut plus tard ne modifie pas un preset existant. Un paramètre absent du fichier revient à son défaut au chargement.
- À faire quand les samples existeront (palier 1/6) : chemins de samples (relatif au preset, absolu, recherche par nom, relocalisation — spec §20), export ZIP portable, presse-papier = sous-arbre JSON, extensions `.neptunepreset` / `.neptunecache`.

## Pistes parallèles (2026-10-14, à valider dans Reaper)

- **Décisions de l'utilisateur** : pool propre de **32** pistes parallèles (elles ne prennent pas les 16 pistes génératrices) ; **somme toujours en fin de chaîne du parent** (après son pan ; pas de point de sommation réglable pour l'instant) ; **solo « en place »** (le parent reste actif et alimente la parallèle, sans être entendu) ; mêmes paramètres d'hôte qu'une piste.
- **Modèle** (`mixer::ParallelSettings`, état schéma **v8**, clé `parallels`) : active, **parent** (0..15 piste, 16..47 piste parallèle), **point de captation** dans la chaîne du parent (les 4 points des envois ; défaut post-pan), une bande complète (nom, couleur, 8 inserts, 8 envois, sortie directe, loi de pan, fader, pan, mute, solo). « Sortie principale activée » = se somme dans le parent. Structure en arbre : une parallèle ne capte que la chaîne de son parent direct ; boucles, parents inactifs ou inexistants sont détachés à la lecture (`fixParallels`) et jamais traités par le moteur.
- **Moteur** : un parent traite son instrument, ses inserts, son fader et son pan, puis ses parallèles (récursif, tampons par profondeur jusqu'à 32) captent leur point, passent par leurs inserts / fader / pan, et se somment dans le signal propre du parent **avant** ses envois, sa sortie directe et sa sortie principale. Le vu-mètre d'une piste montre le total (elle + ses parallèles). Une piste silencieuse n'est ignorée que si ses parallèles le sont aussi (queues d'inserts préservées). Pistes et parallèles forment le même domaine de solo ; le solo d'une piste garde ses parallèles audibles.
- **Paramètres hôte** (`mixer::parallelParam`, ids `5000 + 100.p + offset`) : volume, pan, mute, solo, 8 bypass d'inserts, 8 niveaux d'envoi (26 par parallèle, 832 au total).
- **Interface** : bouton « P » sur chaque piste et chaque parallèle (à côté de M et S) : crée une parallèle juste à droite. La bande parallèle est visuellement distincte (fond de l'application, bord d'accent à gauche), son en-tête indique sa parenté (« P2 <1 »), un menu règle le point de captation, « × » la supprime avec ses descendants (confirmation si elle a du contenu). **Repliement** : les filles d'une parallèle sont masquées par défaut (bouton ▸n / ▾n), elles restent actives dans le moteur. La rangée des pistes défile horizontalement. Retirer une piste retire ses parallèles. Ajouter, retirer ou modifier le parent d'une parallèle vide l'historique d'annulation.
- **Suivi du volume du parent** (décidé le 2026-10-14) : option par parallèle (fenêtre « Routage ») : le gain de fader du parent s'applique aussi à la parallèle (fondu sur le bloc ; le mute du parent la coupe aussi). **Effet seulement pour une captation avant le fader** (points 0 et 1) : après le fader, le signal contient déjà le volume du parent. Les petites-filles suivent le fader de leur parent direct.
- **Décisions** : point de sommation fixe en fin de chaîne (à revoir seulement si le besoin apparaît) ; **le parent d'une parallèle ne change jamais après sa création**.
- **Non fait** : copier-coller d'une parallèle, déplacement par glisser-déposer, repliement mémorisé dans le projet.
- **Point à valider** : profondeur maximale = 32 (le pool) ; le total d'une piste (vu-mètre) inclut ses parallèles.

## Synthé soustractif complet (2026-10-14, à valider dans Reaper)

- **Structure** (spec §2) : 3 oscillateurs + sous-oscillateur + bruit -> mixeur des 5 sources (niveau automatisable, mute, pan) -> 2 filtres (série / parallèle avec balance, chacun avec son enveloppe) -> enveloppe de volume ; enveloppe de pitch dédiée (profondeur ±48 demi-tons automatisable). Polyphonie poly / mono / legato, vol de voix, glissando comme avant.
- **Oscillateurs** : catalogue de **32 formes** (`WaveCatalog.h`), 3 catégories (numérique 10, style analogique 8, complexe 14), noms génériques (« Ladder saw »...). Sinus, triangle, dent de scie, carré et impulsion (largeur automatisable) sont **analytiques à bande limitée** (PolyBLEP / PolyBLAMP) ; les 27 autres sont des **tables d'onde à bande limitée** (une table par octave, 10 niveaux, construites une fois par FFT). Mesuré : aucune forme du catalogue ne dépasse 0,4 % d'énergie hors harmoniques à 1,5 kHz. Réglages par oscillateur : forme, octave, demi-ton, fine tune (automatisable), **unisson 1 à 8 voix** (détune automatisable 0..100 cents, écartement stéréo, courbe linéaire ou « supersaw » en |x|^1,65), retrigger / phase libre, phase de départ, **synchro dure** (oscillateurs 2 et 3 sur le 1, avec correction PolyBLEP à l'instant de la resynchronisation pour les formes à marche : dent de scie, carré, impulsion ; sans correction pour les autres formes).
- **Sous-oscillateur** : sinus / triangle / carré, -1 ou -2 octaves. **Bruit** : blanc ou rose.
- **Paramètres automatisables** (15 par piste, `mixer::synthParam`, ids `1000 + 100.t + 40..54`) : niveaux des 5 sources, fine tune x3, largeur d'impulsion x3, détune d'unisson x3, profondeur de l'enveloppe de pitch ; plus ceux de l'instrument : gain, accordage, coupure et résonance des 2 filtres. Le reste (formes, enveloppes, routage, polyphonie...) est enregistré dans le projet (`SynthDescription`, JSON) et annulable.
- **Interface** : vue Synthé en 3 pages (oscillateurs + sous-osc + bruit ; filtres ; enveloppes + voix), **explorateur de formes** (dalle filtrable par catégorie et par texte, aperçu dessiné de chaque forme), clavier à l'écran. Les potards du bas ne montrent plus que gain et accordage pour un synthé.
- **Coût** (outil de performance, 256 échantillons) : 16 voix à 1 oscillateur ~2,5 % du budget ; 64 voix ~10 % ; **16 voix avec unisson 8 + 2 filtres ~9 %, 64 voix ~38 %** (pire cas).
- **Non fait** : modulation d'un oscillateur par un autre (FM, anneau), explorateur : pas de favoris ; synchro dure sans correction sur les tables d'onde ; pas de preset de son ; les formes « complexes » sont des spectres fixes (pas de table animée).
- **Points à valider à l'oreille** : niveau relatif des sources (somme de plusieurs sources + unisson : peut dépasser le niveau d'une voix seule), courbe supersaw, noms et contenu des formes du catalogue.

## Inserts et premier plugin stock : l'Utilitaire (2026-10-14, à valider dans Reaper)

- **Architecture** (cœur portable, sans JUCE) : `StockModule.h` (un module = DSP + déclaration de ses paramètres propres, identifiants >= 100), `ModuleRunner` (ce que tous les modules ont en commun : trim d'entrée / de sortie, mix, bypass, lissage ; possède le `ParameterSet` du module), `InsertInstance` (un module posé sur un emplacement), registre `availableModules()` / `createInsert()`. `UtilityModule.h` : l'Utilitaire (voir spec §8). Deux adaptateurs : l'insert de Neptune (`Engine`, `NeptuneProcessor`) et le plugin CLAP séparé (`MoussaillonPlugin`). L'interface (`UtilityEditor`, `NeptuneKnob`, `KnobModal`) ne connaît que `ParamHost` (jeu de paramètres + gestes d'édition).
- **Moteur** : 8 emplacements par piste, par bus et sur le Master. Ordre : instrument -> inserts -> fader -> pan ; bus : somme -> inserts -> fader ; master : somme -> trim -> inserts -> fader -> pan -> mono. Les points de captation des envois 0 (pré-inserts) et 1 (post-inserts / pré-fader) sont maintenant distincts. Le bypass d'un emplacement est un **paramètre de l'hôte** (pistes : `kInsertBypass` existant ; bus : `3000 + 100.b + 10..17` ; master : ids 7..14). Remise au thread audio par `HandoffSlot`. Les modules ne sont traités que s'ils sont présents ; un module contourné et fondu terminé n'est plus calculé.
- **Paramètres des inserts : NON exposés à l'hôte** (seulement le bypass). Ils sont enregistrés dans le projet (schéma **v7**, `inserts` dans chaque bande et dans le master), annulables (même historique), mais pas automatisables. À reprendre avec la réflexion sur l'automation (voir `spec-modules.md` §7).
- **Interface** : dans chaque bande (pistes, bus, master) 4 lignes d'inserts visibles sur 8 (molette ou flèche pour les 4 suivantes) ; vide = « + » (menu des modules), rempli = clic pour éditer, clic droit : ouvrir / bypass / retirer. L'éditeur s'ouvre en fenêtre superposée (titre, bypass de l'emplacement, fermer). Les bandes s'adaptent à la hauteur disponible (300 à 360 px) ; fenêtre par défaut 1160 x 960. Ajouter ou retirer un insert vide l'historique d'annulation.
- **Plugin séparé** : cible `Moussaillon` (CLAP `com.tournedosrossini.moussaillon`, nom provisoire ; en-tête « MOUSSAILLON / UTILITY · FLIBUSTE SUITE » en orange comme la maquette de Neptune), état JSON `moussaillon-state`, thème / langue / contraste lus dans le même `settings.json` que Neptune. Compilé, validé par `clap-validator` et archivé par la CI (`Moussaillon-<OS>`).
- **Non fait** : copier-coller de module entre emplacements, déplacement par glisser-déposer des inserts, presets / A/B, aide en ligne, redimensionnement par la poignée de coin NOVA (la fenêtre est redimensionnable par l'hôte), goniomètre, latence PDC (aucun module n'en a pour l'instant).
- **Points à confirmer** : loi du pan double (puissance constante, indépendante de la loi choisie pour le pan simple) ; Mid = (L+R)/2 ; plage des trims ±24 dB.

## Plugins stock : décisions du 2026-10-14

- Les plugins stock sont **intégrés à Neptune ET publiés comme plugins CLAP indépendants** (JUCE, pas DPF), voir `spec-modules.md` §7. Premier lot : l'Utilitaire, dans les deux formes (insert + petit CLAP « NOVA Utility »), pour valider le principe. Les autres plugins plus tard, un à la fois.
